> 日期：2026-10-25
> 对象：SmartBattBox 8S 磷酸铁锂（20Ah，充电器 CV 29.2V，1mΩ 采样，MAX17263 EZ 未特征化）
> 范围：充电启动条件、充电中判定、判满逻辑、停充与冷却、异常处理、显示口径、参数整定

> 依据：UG6597 Rev3（`MAX17263_codex/tmp/pdfs/max1726x-modelgauge-m5-ez-user-guide.txt`）、ADI 主机端软件实现指南、MAX17263 数据手册、原理图

## 1. 背景与约束

| 项 | 值 | 影响 |
|---|---|---|
| 电池 | 8S LFP，20Ah，0.5C 充电（10A） | LFP 平台区 OCV 平，SOC 精度天然受限 |
| 充电器 | CV **29.2V**（3.65V/节），CC 10A | 与早期代码假设的 28.8V(3.6V) 不一致，已统一到 29.2V |
| 采样 | R114 = 1mΩ | 电流 1.5625mA/LSB，满量程 ±51.2A；容量 5mAh/LSB |
| 电量计配置 | EZ（`model=NULL`），ModelID=6(LFP)，FullSOCThr 80%，IChgTerm 200mA | FQ 窗口 25~250mA |
| 板载自耗 | 实测约 **-114mA**（MCU/蓝牙/LDO 由电池节点供电） | 充电时电池净电流 = 充电器电流 − 114mA，直接影响 FQ 窗口 |
| 温度源 | 电量计内部 die 温度；电芯温度走 mod_temp 独立 NTC | die 温度不能用于电芯过温保护 |

## 2. 方案总览

```
[220V 输入]  由输入侧 HLW8110 判定: VIN 在 90~300V 连续 2 次 → AC_PRESENT
                    │
                    ▼
[启动]  AC 稳定 2s && 电池快照有效 && SOC < 100% && !物理满锁存 && !10min 冷却
                    │
                    ├─ CHG_IN 吸合 ──1.5s──► CHG_OUT 吸合 ──► RUNNING
                    ▼
[充电中]  AC 丢失 ──► input_abort() 立即全断（同一 tick）
                    ▼
[判满 A]  SOC=100% 且 FQ=1 且 TTF 剩余=0        → 立即停
          SOC=100% 但 FQ/TTF 未同时满足          → 保持 5min 强制停
[判满 B]  AvgVCell≥3600mV(28.8V) 且 TTF=0
          且 |AvgCurrent|≤500mA 保持 1h          → 停 + 物理满锁存
                    ▼
[停充]  断 CHG_OUT → 1.5s → 断 CHG_IN；置满锁存；10min 冷却
[解锁]  10min 到期 / 拔插 220V；物理满锁存需 SOC<95% 或拔插 220V
```

## 3. 判满逻辑与优先级

| # | 条件（必须处于 `CHARGE_BYPASS` + `RUNNING`） | 动作 | 日志 |
|---|---|---|---|
| A1 | `SOC ≥ 100` 且 `FQ(bit7)=1` 且 `TTF 剩余=0` | 立即停充 | `BAT FULL (FQ+TTF)` |
| A2 | `SOC ≥ 100` 且（FQ 或 TTF 不满足），连续 5min | 强制停充 | `BAT soc=100% but fq=.. ttf=..; force stop in 300s` → `BAT FULL (forced5min)` |
| B | `SOC<100`，`AvgVCell ≥ 3600mV` 且 `\|AvgI\| ≤ 500mA`，连续 1h（**不要求 TTF=0**：本工程 `TTF=(FullCapRep-RepCap)/I`，TTF=0 与 SOC=100 等价，加了会让 B 永远无法在 SOC<100 时触发） | 停充 + 物理满锁存 | `BAT soc=..% but cellAvg=..mV avgI=..; phys full in 3600s` → `BAT FULL (V+I 1h)` |

- **TTF=0 判定**：`ttf_valid=false` 或 `time_to_full_min=0`（充电电流 <50mA 时 TTF 无意义，按 0 计）。
- **B 路径电流取绝对值窗**：末端板载自耗使净电流为小负值（充电已完成），允许；但大电流放电（边充边用/充电器失效）被排除。
- **物理满锁存**：B 触发后置位，只有 `SOC<95%` 或拔插 220V 才解除，防止 SOC 卡 99% 时每 10min 反复充停。

### 3.1 逆变输出电量门限（2026-10-25，门限由 2% 调整为 1%）

| 场景 | 条件 | 动作 |
|---|---|---|
| 开启输出（按键） | 无 220V（将走逆变）且 `SOC < 1%`（即 0%） | 拒绝开启 + **3 声** + 屏显 **ERR17**（3s） |
| 逆变启动（含 220V 掉电自动转逆变） | 进入 `INVERT_STATE_IDLE→PRECHARGE` 前 `SOC < 1%`，或电池数据无效 | 撤销请求、不进预充、**3 声** + **ERR17** |
| 逆变运行中 | `SOC < 1%`（掉到 0%） | 立即撤销请求 → 断 PD0 → 顺序停电，**3 声** |
| 傍路输出（有 220V） | — | **不受电量限制**，照常开启 |

门限 `INV_MIN_SOC_PCT = 1`：`SOC ≥ 1%` 允许逆变，`SOC < 1%`（只有 0%）不允许/自动关断。低电量关断后不会自动重启，需用户再按一次。

**ERR17** 由 `app_ui_show_code()` 产生（瞬时提示码，**10s** 后自动消失，优先级低于真实告警码），避免污染常驻告警。

### 3.2 充电中拔 220V 不鸣蜂鸣器

`input_abort()` 在 `charge_state == STARTING/RUNNING`（CHG_IN/CHG_OUT 已吸合）时撤路**不鸣蜂鸣器**，只在日志标记 `(charging, no beep)`；其它场景（仅旁路、待机）仍保持 3 声提示。

## 4. 关键寄存器依据（UG6597）与本次修正

| 项目 | 结论 | 依据 |
|---|---|---|
| FStat(3Dh) 位定义 | **D0 DNR / D6 RelDt2 / D7 FQ / D8 EDet / D9 RelDt**；旧代码按 bit5(FQ)、bit3(EDet)、bit6(RelDt) 全错，bit5 是 X(Don't Care) | UG6597 Table 20, p39；`max1726x-rs` 库独立佐证 |
| 现场验证 | `fstat=0x5660` → RelDt=1、RelDt2=1（长时间静置）、FQ=0、EDet=0、DNR=0，与 SOC=3% 自洽 | 现场日志 |
| FullSOCThr | EZ 推荐 **80%(0x5005)**；特征化模型才用 95%(0x5F05) | UG6597 p30 |
| FQ 三条件 | `VFSOC>FullSOCThr` 且 `Current` 与 `AvgCurrent` 同时落在 `[0.125,1.25]×IChgTerm`（200mA → 25~250mA） | UG6597 p15/p29 |
| 满电学习 | FQ 触发时芯片按 RepCap 更新 FullCapRep（容量/SOH 学习点） | UG6597 p14 |
| ScOcvLim | 0x479E 正确，编码 `(OCV_Low_Lim<<7)|OCV_Delta` → 3275~3350mV | UG6597 p17 |
| 充电状态 | 芯片**没有**充/放状态位，只能看 Current/AvgCurrent 符号（充电为正） | 数据手册 Status 表 + UG EOC 条件 |
| 初始化序列 | 与 ADI 软件指南一致（POR→DNR→HibCfg→SoftWake→配置→Refresh→恢复→清 POR） | ADI Host-Side 实现指南 |

**已修的关键缺陷**：FQ 位错误导致"芯片判满"从未真正工作；旧固件中 `fq=1` 读到的是未定义位，这正是"满电却 FQ=0/SOC=3% 却 fq=1"矛盾的根因。

## 5. 历史问题闭环

| 问题 | 现象 | 处理 | 状态 |
|---|---|---|---|
| 屏显 100% 而实际 3% | `charge_full` 锁存 + 显示无条件覆盖 SOC | 显示始终用真实 SOC；满锁存只关图标；锁存退出条件明确 | ✅ 已修 |
| FQ 位错误 | 判满永远不生效 | bit5→bit7，并新增 0x5660 反推验证 | ✅ 已修 |
| 满后不再补电 / 反复补电 | 锁存只靠电流解除 | 改为 SOC<100 启动 + 10min 冷却 + 物理满锁存 | ✅ 已改 |
| 判满依赖 FQ（该硬件可能不置位） | 净电流被 114mA 偏置 | A2 强停 + B 物理兜底 | ✅ 已覆盖 |
| 单次采样失败即跳闸 | 数据链过严 | 稳态 2s 去抖、启动中立即跳闸 | ✅ 已改 |

## 6. 风险清单

| 编号 | 风险 | 影响 | 严重度 | 缓解/建议 |
|---|---|---|---|---|
| R1 | `SOC=100` 可能早于真满（FullCapRep 学小） | 提前停充，实际容量偏低 | 中 | 观察 `fullcap`/`soh` 趋势；必要时对电芯特征化；或把 A 路径也加电压门槛（≥3600mV） |
| R2 | B 路径触发后，SOC 停在 95~99 时不再自动补电 | 长时间不充（直到 SOC<95 或拔插） | 低 | 符合"避免反复充停"的设计意图；如需更积极可把 `CHARGE_FULL_PHYS_REARM_SOC` 调到 98 |
| R3 | 满后继续插 220V：自耗 114mA → 约 50min 掉 1% | 约每小时吸合一次充电继电器 | 中 | `CHARGE_RESTART_SOC` 改 98（~3.5h）/95（~9h） |
| R4 | FQ 在本硬件可能长期不置位（净电流偏置、VFSOC<80%） | A1 无法使用，退化为 A2 强停 | 低 | 已由 A2 覆盖；FQ 仅作"加速/可选" |
| R5 | 电压门槛 3600mV 依赖未校准的 CELLX 增益（±0.5%≈±18mV/节） | B 路径可能过严/过松 | 中 | 实测 CV 时 `avg_cell_voltage_mv` 与万用表对比，必要时调 `CHARGE_FULL_V_MV` |
| R6 | 边充边用（旁路负载 > 充电器）时净电流为负、电压低 | 不会误判满（绝对值窗+电压门槛） | 低 | 已验证逻辑；建议台架复测 |
| R7 | 判满期间电池数据无效 | 判满不动作，充电继续 | 低 | `battery_protect` 稳态 2s 后跳闸，作为兜底 |
| R8 | 本次改动未编译 | 可能存在编译/笔误 | 高 | CubeIDE 编译 + 台架验证（§8） |
| R9 | `BATTERY_PROFILE_ID` 已 7，芯片未断电 | 暖启动 `M_EPROFILE`，电池数据无效 | 高 | 烧录后**给 MAX17263 完整断电一次** |
| R10 | Config2 的 `0x0080` 位语义未核实（dSOCen/TAlrtEn） | 仅影响 ALRT 引脚，不影响判断 | 低 | 后续用 UG 或实测确认 |
| R11 | `VEmpty=2.5V` 与软件 UV=2.5V 重合 | 0% 与跳闸同点，空电学习与保护同时触发 | 中 | 建议 UV 提到 2.6~2.7V，或 VE 降到 2.4V |
| R12 | LFP 低温禁充未由电量计保证 | die 温度不代表电芯 | 中 | 充电前用 mod_temp 的 NTC 做 0℃ 以下禁充 |

## 10. 评审结论

**有条件通过。** 方案满足产品定义（220V 判输入、SOC<100 启动、SOC=100 判满 + 5min 强停、物理兜底、10min 冷却、拔枪即断），并修正了 FQ 位、显示覆盖、单次采样跳闸三个实质缺陷。

放行条件（必须全部满足）：

1. **编译通过**（本次改动未在本机编译，环境 shell 不可用）；
2. 烧录后**给 MAX17263 完整断电一次**（`PROFILE_ID=7`），确认日志无 `M_EPROFILE`；
3. 完成 V1/V2/V4 三个用例，且日志中出现 `BAT FULL (...)`、`phys full in 3600s`、`restart block` 三类记录；
4. 实测确认 `avg_cell_voltage_mv` 在 CV 时与万用表一致（误差 <1%），据此定 `CHARGE_FULL_V_MV`。

**遗留待决（不影响本次放行，但需排期）**：R3（插电待机补电间隔）、R11（VEmpty/UV 重合）、R12（低温禁充）、电芯特征化（SOC 精度与 FullCapRep 学习质量）。
