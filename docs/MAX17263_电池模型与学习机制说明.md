## 0. 三个问题的速答

| 问题 | 速答 |
|---|---|
| ① 电池模型怎么做 | 寄样电芯给 ADI 做特征化 → 拿回 INI（32 字模型表 + RCompSeg/QR/参数）→ 转成 C 数组填入 `max17263_model_t` → 代码在 **每次 POR** 把它写进芯片 RAM（芯片掉电即丢，必须重载） |
| ② 没模型怎么学习 | 芯片自己学（满电学容量、静置学内阻），主机只负责**保存/恢复 5 个寄存器**；当前代码已实现（W25Q128 CRC 日志 + POR 恢复），但学习质量受 EZ 精度限制 |
| ③ 当前参数 | 13 个 `battery_cfg` + 14 个 `battery_policy` + 8 个应用层充电判满参数 + 驱动内固定量，见 §3 |

## 1. 电池模型（Characterization）

### 1.1 模型解决什么问题

ModelGauge m5 的 SOC 由「电压法（VFG，靠 OCV-SOC 曲线）」与「库仑计」混合而成。EZ 模式用的是一条**通用锂电池 OCV 曲线**（LFP 时 ModelID=6 的通用曲线）；磷酸铁锂平台区（约 3.2~3.35V）电压差几十 mV 就对应几十 % SOC，通用曲线必然不准。特征化模型就是把「你这颗电芯」的真实 OCV/内阻/温度特性写进芯片，替换通用曲线。

模型在芯片里是 **RAM**：`ModelCfg.Refresh`/`LdMdl` 把模型装进算法，**掉电即丢**，每次 POR 必须重新装载（ADI 的流程就是这样设计的）。

### 1.2 需要准备/提供什么数据

**给 ADI 特征化服务的输入**（官方途径，不是自己算）：

| 类别 | 内容 |
|---|---|
| 电芯样品 | 同批次、与量产一致的电芯（通常若干只），注明型号/厂家/规格书 |
| 电芯规格 | 标称/最小/最大容量、充电截止电压、放电截止电压、标准/最大充放电倍率、允许温度范围 |
| 应用条件 | 实际 CC/CV（本项目 10A / 29.2V）、充电终止电流（IChgTerm）、典型放电曲线/负载、工作温度范围、静置习惯 |
| 硬件参数 | Rsense（1mΩ）、多串数（8S）、CELLX 分压（1:20）、是否用外部 NTC（本项目用内部 die 温度） |

**自己先要测/确认的数据（用于验收，不用于生成模型）**：

| 数据 | 方法 | 用途 |
|---|---|---|
| 实际可用容量 | 0.2C 恒流放电到 2.5V/节，外接库仑计积分 | 与 `FullCapRep` 收敛值对照，定 `design_mah` |
| 直流内阻 | 1C 阶跃测 ΔV/ΔI | 判断 `RComp0` 是否合理 |
| OCV-SOC 曲线 | 每次放 5% 后静置 ≥2h 测 OCV（20/30/40℃ 各一组） | 验证模型曲线形状、判断平台区位置 |
| 充电 taper 曲线 | CC→CV 全程记录电流 | 定 `IChgTerm`（FQ 窗口中心） |
| 温升 | 满功率放电时电芯表面温度 | 定 `TAlrt` 与风扇/保护阈值 |

### 1.3 ADI 会返回什么（INI 内容 → 寄存器）

特征化完成后 ADI 会给出一个 INI 文件，本质是一组「寄存器地址 = 值」。与 MAX17263 的对应关系：

| INI 内容 | 寄存器 | 本项目驱动字段 |
|---|---|---|
| OCV 表 16 字（OCVTable0~15） | 0x80 ~ 0x8F | `model->table[0..15]` |
| X 表 16 字（XTable0~15） | 0x90 ~ 0x9F | `model->table[16..31]` |
| RCompSeg | 0xAF | `model->rcompseg` |
| RComp0 | 0x38 | `model->rcomp0` |
| TempCo | 0x39 | `model->tempco` |
| QRTable00/10/20/30 | 0x12 / 0x22 / 0x32 / 0x42 | `model->qr[0..3]` |
| DesignCap / IChgTerm / VEmpty | 0x18 / 0x1E / 0x3A | 仍由 `battery_cfg` 提供 |
| FullSOCThr | 0x13 | `battery_cfg.full_soc_thr_pct`（**特征化后应改 95%**） |
| LearnCfg / RelaxCfg / Config / Config2 / TGain / TOff / Curve / MiscCfg / ScOcvLim | 0x28 / 0x2A / 0x1D / 0xBB / 0x2C / 0x2D / 0xB9 / 0x2B / 0xD1 | `model->optional[]`（驱动白名单，超过白名单的地址会被拒绝） |

### 1.4 怎么导入芯片（两条路径）

**A. 产品固件路径（推荐，本项目已实现）**

1. 把 INI 转成 C 数组（注意：寄存器是 16 位、低字节先发；INI 里通常已是 4 位十六进制字）：

```c
/* battery_model_lfp8s.h（新建文件，示例结构） */
static const max17263_model_t battery_model_lfp8s = {
    .table = { 0x1234, 0x2345, /* 32 个字，来自 INI 的 80h~9Fh */ },
    .rcompseg = 0x1234,                 /* AFh */
    .rcomp0   = 0x1234,                 /* 38h */
    .tempco   = 0x1234,                 /* 39h */
    .qr = { 0x1234, 0x2345, 0x3456, 0x4567 },  /* 12h/22h/32h/42h */
    .optional = (const max17263_reg_value_t[]){
        { 0x13, 0x5F05 },   /* FullSOCThr = 95%（特征化后） */
        { 0x28, 0x4486 },   /* LearnCfg 等，按 INI 填 */
    },
    .optional_count = 2,
};
```

2. `battery_config.h` 里把 `.model = NULL` 改为 `.model = &battery_model_lfp8s`，并按需把 `full_soc_thr_pct` 改 **95**；
3. **bump `BATTERY_PROFILE_ID`**（模型内容参与 `battery_profile_hash()`，bump 后旧的 Flash 学习记录会自动失效）；
4. 编译烧录，**给 MAX17263 完整断电一次**（否则暖启动不会重装模型）。

内核流程（`drv_max17263_load_full_model()`，已实现 ADI Option 3）：

```
写 ModelCfg(保留 VSEL/CSEL, ModelID=6, 0x0060)
→ Lock1=0x0059, Lock2=0x00C4（解锁模型区）
→ 逐字写 0x80~0x9F（每个都回读校验）
→ 写 RCompSeg(0xAF)
→ 上锁：Lock1=0, Lock2=0，并回读 0x80~0x9F 必须全 0
→ RepCap=0, DesignCap
→ 容量恢复序列（FullCapRep→dQAcc→dPAcc→FullCapNom→MixCap/AvCap→RComp0/TempCo）
→ IChgTerm, VEmpty
→ QR 表 0x12/0x22/0x32/0x42
→ optional 列表
→ Config2 |= 0x0020（LdMdl），轮询清零（期间写 Current/AvgCurrent=0）
→ 再写 QR20/QR30、Cycles
→ 恢复 HibCfg → 清 POR
```

**B. 产线/实验路径**：用 ADI 的 MAX1726x 评估软件或主机脚本按上面同样的顺序写（掉电即失效，每次上电都要写）。适合验证模型，不适合量产固件。

### 1.5 本项目现状

| 项 | 状态 |
|---|---|
| 模型装载代码 | ✅ 已实现（`drv_max17263_load_full_model`，含解锁/上锁/校验/LdMdl/恢复 HibCfg） |
| 模型数据 | ❌ 没有（`model = NULL`，走 EZ；启动日志 `EZ uncharacterized`，故障位 `BAT_WARN_UNCHARACTERIZED`） |
| 模型导入文档/工具 | ❌ 没有 INI→C 的转换脚本，需要手写或补一个脚本 |
| 特征化后的参数联动 | ⚠️ 需改 `full_soc_thr_pct`（80→95）、bump PROFILE_ID、给芯片断电 |

### 1.6 不做特征化的替代方案

1. 保持 EZ（当前状态），接受 LFP 平台区 SOC 误差（数 %~10%）；
2. 用 EZ + `ScOcvLim` keep-out（3275~3350mV，已配置）+ FullSOCThr 80%（已配置）缓解；
3. 主机侧用「满/空锚点」修正显示：满 = 本项目的判满逻辑，空 = EDet/2.5V；
4. 不要自己伪造 OCV 表（驱动注释明令禁止），伪表比通用表更糟。

## 2. 无模型（EZ）时芯片怎么学习

### 2.1 芯片自动学的三件事

| 学习事件 | 触发条件 | 芯片内部动作 | 对应寄存器 |
|---|---|---|---|
| **满电学习** | EOC：`VFSOC > FullSOCThr` 且 `Current`、`AvgCurrent` 都落在 `[0.125, 1.25]×IChgTerm` | 按 `RepCap` 更新满容量 | FullCapRep(0x10)、FullCapNom(0x23) |
| **静置学习** | 电池静置（RelDt/RelDt2 事件） | 修正 OCV 模型与内阻补偿 | RComp0(0x38)、TempCo(0x39) |
| **混合权重推进** | 完成充放循环 | LearnCfg.LS 0→7（约 2 个完整循环），库仑计权重逐步占主导 | LearnCfg(0x28)、Cycles(0x17) |

> 注意：满电学习点是**容量/SOH 的唯一来源**；如果 FQ 从不触发，`FullCapRep` 永远是 DesignCap，SOH 恒 100%。本项目 FQ 位已修正为 bit7，但本硬件净电流被板载自耗（约 114mA）偏置，FQ 可能不置位 → 因此加了「SOC=100 强停」与「电压+电流 1h 物理兜底」。

### 2.2 主机必须保存什么

`max17263_learned_t`（5 项，全部是寄存器原始值，不做换算）：

| 字段 | 寄存器 | 作用 |
|---|---|---|
| `rcomp0` | 0x38 | 内阻补偿基准，恢复后 OCV 估计才正确 |
| `tempco` | 0x39 | 内阻温度系数 |
| `fullcaprep` | 0x10 | 学到的满容量（报告值），SOC 的分母 |
| `fullcapnom` | 0x23 | 滤波后的满容量 |
| `cycles` | 0x17 | 循环计数（0.01 次/LSB） |

### 2.3 怎么写回芯片（ADI 规定顺序 + 本代码）

**只在 POR 后写**（芯片真掉电、RAM 已丢）。顺序（`drv_max17263_load_capacity()`，与 ADI Option 3 一致）：

```
写 FullCapRep(0x10) = fullcaprep
写 dQAcc(0x45) = fullcapnom / 2
写 dPAcc(0x46) = 0x0C80
延时 10ms
写 FullCapNom(0x23) = fullcapnom
读 VFSOC(0xFF) → MixCap(0x0F) = AvCap(0x1F) = VFSOC/25600 × fullcapnom
延时 200ms
写 RComp0(0x38)、TempCo(0x39)
（完整模型路径另写 Cycles(0x17)）
```

**不能做的事**：直接写 RepSOC(0x06)/RepCap(0x05)——它们是算法输出，只读；需要重估 SOC 时用 `Quick Start`（MiscCfg bit10=0x0400，自清零）。

### 2.4 当前代码的实现情况

| 环节 | 实现 | 位置 |
|---|---|---|
| 学习参数读取 | ✅ `drv_max17263_get_learned()`：读前读后查 POR、查 FStat.DNR、容量合理性筛查 | `drv_max17263.c:740` |
| 合理性筛查 | ✅ `[DesignCap/10, DesignCap×2]`，仅防损坏，不是 SOH 标准 | `drv_max17263.c:312` |
| 持久化 | ✅ W25Q128 扇区 9/10（0x9000~0xAFFF），64B/记录，含 magic/版本/seq/**配置 hash**/**电池 ID**/CRC32/**最后写 COMMIT** | `mod_battery.c` |
| 保存时机 | ✅ 距上次 ≥60s 且 Cycles 跨过 64 个原始计数（0.64 循环）；关机时 `mod_battery_checkpoint()` | `mod_battery.c:329` |
| 恢复时机 | ✅ **仅 POR**；暖启动（MCU 复位）只校验配置，不覆盖芯片当前学习值 | `drv_max17263.c:512` |
| 换电池 | ✅ `BATTERY_PACK_ID` 变更 → 旧记录失配 → 当新电池重新学习 | `battery_config.h` |
| 新电池初值 | ✅ 无记录且 RepSOC<5% 时触发 Quick Start（基于 OCV 重估） | `mod_battery.c:87-103` |
| 循环计数 | ✅ 0.01 次/LSB；≥65000 时置 `BAT_WARN_CYCLE_RANGE` 维护提示 | `mod_battery.c:321` |

**没有实现的**：
- 没有「学习过程可视化」的 CSV（`BATTERY_CSV_ENABLE` 只在旧文档里，当前代码没有），只有 10s 一条的 `[BAT]` 日志；
- 没有电池在位检测（Bst 需要外部 NTC，本项目用内部温度）；
- 模型路径的 optional 白名单之外寄存器会被拒绝（有意设计）。

### 2.5 学习期间要采集什么（验收用）

| 数据 | 频率 | 用途 |
|---|---|---|
| `soc` / `vfsoc` / `repcap` / `fullcap` | 10s（现有日志） | 看 SOC 与容量是否收敛、满电点是否在 3.6~3.65V |
| `cur` / `avgcur` | 10s | 判断 FQ 窗口（25~250mA）是否被穿越 |
| `fstat`（尤其 bit7 FQ、bit8 EDet、bit9/6 静置） | 10s | 判断是否真的发生了满电/空电学习 |
| `temp`（die）+ NTC 三路 | 10s | 温度补偿与保护 |
| `cycles` 原始值 | 10s | 判断学习进度与 Flash 保存时机 |
| 外部库仑计 Ah | 全程 | 与 `repcap` 对照，得到真实误差 |
| Flash 记录（重启后） | 每次开机 | 确认恢复是否成功（日志无 `BAT FAIL/NVM`） |

建议流程：满充 1 次 → 静置 2h → 0.5C 放电到截止 → 静置 → 再满充，重复 3 轮，观察 `fullcap` 收敛。

### 2.6 电池拔掉 / 重启 / 换电池的影响（电量计在板上）

这是本项目最容易踩坑的地方：**电量计测的是「电池端子节点」的电压，不是电芯内部**。

| 场景 | 电量计供电 | 芯片状态 | 影响 |
|---|---|---|---|
| **A. 整机断电换电池**（电池是唯一电源） | 掉电 | POR，RAM 学习值全丢 | 下次上电：Flash 有有效记录 → 恢复 5 项学习值；无记录 → 从 DesignCap + OCV 重新开始。**SOC 由 OCV 重估，可能跳变**。最多丢失上次 checkpoint 之后的变化（≤0.64 循环或 60s） |
| **B. 带电拔电池，且接着 220V** | 由 3.3V 电源轨供电（源自充电器） | **不掉电**，学习值保留 | ⚠️ **CELLX 分压看到的是充电器 29.2V → VCell≈3.65V/节 → VFSOC 直接判成 100%**；同时电流是板载负载（约 -0.1A）。接线恢复后 SOC 会长时间偏高，直到库仑计/OCV 纠正。**这就是"放空后重启显示 100%"最可能的成因** |
| **C. 带电拔电池，无 220V** | 掉电 | 同 A | 同 A |
| **D. 换另一组电池** | — | 同 A | 若 `BATTERY_PACK_ID` 没改，旧学习记录会被误用到新电池上（容量/内阻都不对）→ **换电池必须改 `BATTERY_PACK_ID`** |
| **E. BMS 自我保护断开** | 同 B | 不掉电 | 同 B，且 `battery_protect` 可能因电压/数据异常跳闸 |

补充：
- 芯片的 BATT 引脚由 3.3V 电源轨供电（多串方案要求 2.3~4.9V），所以**电池拔出不会让芯片 POR**，只要还有 220V；
- 电池在位检测：Status.Bst 依赖 TH 引脚热敏（本项目 TH 未接 NTC，改用内部温度），**当前无法通过芯片判断电池是否插上**；
- 建议（后续可选）：在「AC 在、电流≈负载电流、电压≈充电器 CV」这种组合下判定"电池未接/断线"，避免把充电器电压当电池电压学进去。

## 3. 当前配置参数全表

### 3.1 `battery_cfg`（`Module/Inc/battery_config.h`，13 项）

| 参数 | 当前值 | 写入寄存器/作用 | 影响 |
|---|---|---|---|
| `profile_id` | **7** | 不写芯片；参与 Flash 记录 hash | 改动任意配置后必须 bump，否则旧学习记录被误用 |
| `battery_id` | **1** | 不写芯片；记录匹配 | **换电池必须改**，否则沿用旧电池学习值 |
| `rsense_uohm` | 1000 | 换算用（不写芯片） | 错 → 电流/容量整体比例错 10 倍级 |
| `design_mah` | 20000 | DesignCap(0x18)=4000 | SOC 分母的初始值、学习边界（1/10~2×）；错 → SOC 整体缩放 |
| `ichgterm_ma` | 200 | IChgTerm(0x1E)=128 | 决定 FQ 电流窗（25~250mA）；与实际 taper 不符 → FQ 不触发或提前 |
| `empty_mv` | 2500 | VEmpty VE=250（10mV/LSB） | 0% 点与空电学习点；高于系统截止 → 永远学不到空 |
| `recovery_mv` | 3000 | VEmpty VR=75（40mV/LSB） | 空电检测的恢复点（回滞） |
| `full_soc_thr_pct` | 80 | FullSOCThr(0x13)=0x5005 | FQ 的 VFSOC 门限；EZ 用 80，特征化后用 95；过高 → FQ 不触发、容量不学习 |
| `series_cells` | 8 | 不写芯片；`pack_mv = cell×8` | 错 → 整包电压显示错 |
| `external_ntc` | false | Config 掩码 0x0200（Ten=1, TSel=0） | 用内部 die 温度；die≠电芯温度 |
| `ntc_100k` | false | ModelCfg bit13(R100) | 仅外部 NTC 时用 |
| `allow_uncharacterized` | true | 不写芯片；`bind()` 放行 EZ | 量产应改 false 并上模型 |
| `model` | NULL | 有值时走 Option 3 装载模型 | NULL=通用 EZ 曲线 |
| `poll_timeout_ms` | 3000 | 轮询 DNR/Refresh/LdMdl 超时 | 过短 → 初始化偶发失败 |

由上面换算出的实际写入值：

| 寄存器 | 值 | 含义 |
|---|---|---|
| DesignCap 0x18 | 0x0FA0 (4000) | 20Ah @1mΩ（5mAh/LSB） |
| IChgTerm 0x1E | 0x0080 (128) | 200mA（1.5625mA/LSB） |
| VEmpty 0x3A | 0x7D4B | VE=2.50V，VR=3.00V |
| FullSOCThr 0x13 | 0x5005 | VFSOC 80% 判满门限 |
| ModelCfg 0xDB | 0x0060 + Refresh | ModelID=6（LFP），保留 VSEL/CSEL |
| ScOcvLim 0xD1 | 0x479E | OCV keep-out 3275~3350mV（编码 `(low<<7)|delta`） |
| Config 0x1D | 0x0200（掩码 0x87D8） | 内部温度、非粘滞、不关机 |

### 3.2 `battery_policy`（14 项，软件判定 + 写告警阈值）

| 参数 | 值 | 作用 | 影响 |
|---|---|---|---|
| `min_cell_mv` | 2500 | 欠压故障 + VALRT 下限 | 与 VEmpty 相同 → 0% 与跳闸同点 |
| `max_cell_mv` | 3720 | 过压故障 + VALRT 上限 | CV 3.65V/节 → 余量 70mV |
| `min_temp_c` | -20 | 低温故障 + TAlrtTh | LFP 充电下限应 0℃（当前未单独限制） |
| `max_temp_c` | 60 | 高温故障 + TAlrtTh | die 温度不代表电芯 |
| `low_soc` | 10 | 低电量告警 + SAlrtTh | 仅提示，不动作 |

### 3.5 参数改动的联动规则

| 改动 | 必须做的事 |
|---|---|
| `profile_id`/`design_mah`/`ichgterm_ma`/`empty_mv`/`recovery_mv`/`rsense`/`series_cells`/模型内容 | **bump `BATTERY_PROFILE_ID`** → 旧学习记录失效 |
| 换电池组 | **改 `BATTERY_PACK_ID`** |
| 任何写入芯片的配置（DesignCap/IChgTerm/VEmpty/FullSOCThr/ModelCfg/ScOcvLim/Config） | **给 MAX17263 完整断电**（MCU 复位不够），否则暖启动报 `M_EPROFILE` |
| `policy` 阈值（电压/电流/温度） | 写告警寄存器，无需断电，但下次初始化生效 |
| 应用层判满参数 | 不影响芯片，重新编译烧录即可 |

## 4. 风险与建议

| # | 问题 | 建议 |
|---|---|---|
| 1 | 无特征化模型，LFP 平台区 SOC 误差大 | 量产前寄样电芯做 ADI 特征化；过渡期接受 ±10% 并靠满/空锚点 |
| 2 | 带电拔电池 + 接 220V 会把充电器电压当电池电压（100% 假电量） | 增加"电池未接"判据（AC 在 + 电流≈负载 + 电压≈CV + SOC 跳变），或要求换电池必须整机断电 |
| 3 | 换电池未改 `BATTERY_PACK_ID` | 产线增加电池 ID 写入流程 |
| 4 | FQ 可能不触发（净电流偏置） | 已用 SOC=100 强停 + 物理兜底；建议实测末端净电流，必要时把 IChgTerm 调到窗口中心 |
| 5 | 学习值只在 POR 恢复 | 保持现状（暖启动不覆盖），但要注意 `PROFILE_ID` 变更后必须断电一次 |
| 6 | die 温度不是电芯温度 | 低温禁充/过温保护继续走 mod_temp 的 NTC |
| 7 | 无 CSV 曲线记录 | 若要评估学习过程，临时在 PC 端记录串口日志（10s 一行）或用调试器抓变量 |
