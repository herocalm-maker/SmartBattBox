# SmartBattBox MAX17263集成变更与验证

## 配置和首次运行

入口仍为 SensorTask -> mod_battery_init/handler。纯寄存器层为 BSP/Driver/Src/drv_max17263.c；电池应用、学习日志及RTOS适配合并在 Module/Src/mod_battery.c，公开接口见 mod_battery.h/app_battery.h。驱动接口统一采用 drv_max17263_* 前缀（例如 drv_max17263_initialize、drv_max17263_sample），工程内调用已迁移。

集中配置：Module/Inc/battery_config.h。已确定8S、1mΩ、CELLX硬件分压1/20、内部温度、12灯。参数：20Ah设计容量、IChgTerm=200mA（FQ电流窗口25~250mA，raw 0x0080）、FullSOCThr=80%（raw 0x5005，EZ未特征化模型ADI推荐值）、满电28.8V（3600mV/cell）、2.5V空电/3V恢复、3.7V过压、10A充电/42A放电。满电28.8V为产品定义值，需实测充电器CV后确认（若电芯规格为3.65V则CV=29.2V）。ModelID=6，未提供实电芯定制模型时持续标记BAT_WARN_UNCHARACTERIZED。容量型SOH不能替代实测健康度。

## 2026-10-25 判满口径修正

原配置按"产品定义满电 28.8V(3.60V/节)"编写，但原理图充电器实测 CV=29.2V(3.65V/节)，导致过压阈值只剩 50mV/节余量、判满电压门槛提前满足。本次统一到 29.2V 口径：

1. `battery_config.h`：`BATTERY_FULL_CELL_MV` 3600→**3650**；`max_cell_mv` 3700→**3720**（VALRT=0xBA7D）；`full_soc_thr_pct` 维持 **80%**（FullSOCThr=0x5005；UG6597 p30 明确 EZ 用 80%、特征化模型才用 95%，90% 会让 VFSOC 够不到门槛导致 FQ 永不触发）；`BATTERY_PROFILE_ID` 5→**7**。
2. `app_main_task.c`：判满兜底 SOC 门槛 95%→**90%**；`charge_full` 锁存新增 SOC 回落解除（SOC<85% 连续 10min，与 90% 判满门槛形成回差）；`battery_protect()` 恢复"启动中立即跳闸 / 稳态连续无效满 2s 才跳闸"，单次采样失败或芯片 DNR 不再直接停机。
3. `mod_battery.c`：启动日志口径改为 `CV 29.2V/3650mV cell`。

必做：改参数后须 bump PROFILE_ID **并给 MAX17263 完整断电**（MCU 复位不够），否则暖启动报 `M_EPROFILE`。

验证状态：本次仅静态代码/文档改动，未在本机编译（环境 shell 不可用），需在 STM32CubeIDE 重新编译，并做"满充看 FQ"、"满充后 10min 是否重复补电"、"85% 静置插电是否正常充"、"充电中单次 I2C 失败是否不再跳闸"四项台架验证。

### 追加：现场"电量 3% 屏显 100%"修复

现场：`soc 3%, vol 24422mV, cur -134mA`，串口屏显示 100%。根因两条叠加：① 旧逻辑里 `charge_full` 锁存只有"平均电流 < -100mA"才解除，而空载自耗（MCU/蓝牙/LDO 均取自电池）约 100mA，正好卡在死区附近，锁存一直不释放；② `display_refresh()` 无条件 `soc = bat_full ? 100 : bat->soc`，把锁存直接显示成 100%。同一状态还会让 `need_charge` 恒为假 → 电量耗尽也不补电。

修复（统一"满"的口径，任何一处都不再单看标志位）：

1. ~~新增 `battery_full_state()` / `battery_full_active()`：满 = (FQ 或兜底锁存) 且 SOC>=90%~~ —— 已被文末"充电/判满最终口径"取代：判满改为 SOC=100%，FQ/TTF 仅用于是否立即停。
2. 串口屏 SOC **始终显示电量计真实值**，只有满充且 RepSOC>=99 才补成 100；不再出现"3% 显示 100%"。
3. `CHARGE_STATE_IDLE→STARTING` 时若 `charge_full` 仍置位则清锁存并记日志，避免"补到 90% 又被判满截断"的小幅循环。
4. 诊断日志新增 `[BAT] mode/chg/need/blk/full` 一行：`mode`=工作模式、`chg`=充电状态机、`need`=补电请求、`blk`=充满停充后封锁剩余秒、`full: fq/latch/app`=芯片FQ/应用锁存/产品级"满"（app 需 SOC>=90），并带 `fstat`；数据无效时也会打印 mode/chg/need/blk/latch。可一眼区分"没充电"是策略、封锁还是数据问题。

仍未处理：① FQ 判满尚未在应用层锁存（`charge_full` 仅由兜底路径置位，FQ 停充后"满"状态只存在于芯片实时位；现由 SOC>=90 门槛兜底）；② `VEmpty` 2.5V 与软件 UV 2.5V 重合，0% 与跳闸同点；③ ~~ScOcvLim=0x479E 位域需按 UG6597 复核~~ —— 已复核：编码为 `(OCV_Low_Lim<<7)|OCV_Delta`，0x479E → 0x8F/0x1E → 3275~3350mV，**代码正确**；④ Config.ETHRM=0 时温度通道是否有效 —— 现场日志 `[BAT] temp: 25.7C` 与 NTC 25.5C 一致，说明内部温度通道有效，此项可关闭。

### 追加：依据 UG6597 的寄存器审计（2026-10-25）

参考资料：`MAX17263_codex/tmp/pdfs/max1726x-modelgauge-m5-ez-user-guide.txt`（UG6597 Rev3）、`modelgauge-m5-host-side-software-implementation-guide.txt`、`max1726x-rs-main/src/registers.rs`。

1. **FStat(3Dh) 位定义全部更正**（UG6597 Table 20, p39；Rust 库 `registers.rs` 独立佐证）：
   | 位 | 名称 | 旧代码 | 正确 |
   |---|---|---|---|
   | D0 | DNR | 0x0001 ✓ | 0x0001 |
   | D6 | RelDt2（长静置） | 当作 FQ 的"RelDt" | 0x0040 |
   | **D7** | **FQ** | 0x0020 ✗ | **0x0080** |
   | **D8** | **EDet** | 0x0008 ✗ | **0x0100** |
   | D9 | RelDt（完全静置） | 未使用 | 0x0200 |

   现场 `fstat=0x5660` 用正确位定义解读完全自洽：RelDt=1、RelDt2=1（长时间静置）、FQ=0、EDet=0、DNR=0，其余 4 位为 X(Don't Care)。旧代码把 X 位当 FQ，才出现"SOC=3% 却 fq=1"的矛盾。
2. **FullSOCThr 保持 80%**：UG6597 p30 明确"EZ Performance 推荐 80%(0x5005)，特征化模型 95%(0x5F05)"；90% 反而可能让 VFSOC 够不到门槛而 FQ 永不触发（容量不学习）。`BATTERY_PROFILE_ID` 6→7。
3. **IChgTerm=200mA 正确**：FQ 三条件 = VFSOC>FullSOCThr + Current∈[0.125,1.25]×IChgTerm + AvgCurrent 同区间 → 窗口 25~250mA。
4. **充电判定**：芯片无"正在充电"状态位，只能看 Current(0Ah)/AvgCurrent(0Bh) 符号（充电为正，由 EOC 条件隐含）。
5. **初始化序列与 ADI 软件指南一致**：POR(Status bit1) → 等 DNR → 存 HibCfg → 写 0x60=0x0090 → HibCfg=0 → 0x60=0 → DesignCap/IChgTerm/VEmpty/FullSOCThr → ModelCfg(0x0060|Refresh) 轮询 → 恢复 HibCfg → 清 POR；学习值恢复序列（FullCapRep→dQAcc=FullCapNom/2→dPAcc=0x0C80→10ms→FullCapNom→按 VFSOC 算 MixCap/AvCap→200ms→RComp0/TempCo）与 ADI Option 3 一致。

### 充电/判满最终口径（2026-10-25 产品定义）

规则（实现于 `app_main_task.c`）：

| 环节 | 条件 | 动作 |
|---|---|---|
| 启动 | 220V 已确认稳定 2s、电池快照有效、`SOC < CHARGE_RESTART_SOC(100%)`、不在冷却期 | CHG_IN 1.5s → CHG_OUT → RUNNING |
| 判满-立即停 | `SOC=100%` 且 `FQ(bit7)=1` 且 `TTF 剩余=0` | 断 CHG_OUT |
| 判满-强制停 | `SOC=100%` 但 FQ/TTF 未同时满足，连续 5min | 断 CHG_OUT（日志 `forced5min`） |
| 判满-物理兜底 | `AvgVCell ≥ 3600mV(=28.8V/8)` 且 `TTF 剩余=0` 且 `AvgCurrent ≤ 500mA`，连续 1h | 断 CHG_OUT（日志 `V+I 1h`），并置物理满锁存：SOC<95% 或拔插 220V 才允许再充 |
| 冷却 | 停充后 10min（`CHARGE_RESTART_BLOCK_MS`） | 期间不启动；拔插 220V 立即解除 |
| 拔枪 | 充电中 AC 丢失 | `input_abort()` 立即全断（同一 tick） |
| 新一轮 | IDLE→STARTING 时清 `charge_full` 锁存 | 显示退出"满" |

日志关键字：`BAT soc=100% but fq=.. ttf=..min; force stop in 300s`、`BAT FULL (FQ+TTF|forced5min): ... block 600s`、`auto chg: restart block expired (10min)`。

已知边界：① SOC 到不了 100% 的情况已由"物理兜底"（电压+TTF+电流 1h）覆盖，停充后靠物理满锁存避免反复补电（SOC<95% 或拔插 220V 解锁）；② 满后插着 220V 时，板子自耗约 114mA 会让 SOC 约 50min 掉 1%，即每 ~50min 补一次电；把 `CHARGE_RESTART_SOC` 改 98/95 可把间隔拉到 ~3.5h/~9h。

## 数据/接口

battery_get_snapshot复制一致快照，valid=false或超过3500ms不用于控制。整包电压mV、电流int32 mA、充正放负，RepSOC/RepCap为报告口径。平均电流另有字段；温度0.1℃；cycles_raw以0.01等效循环为单位；TTE/TTF各有valid标志。故障历史与当前故障分开。主任务对持续2秒的数据失效或方向相关电压/电流故障断开电池通路并进入FAULT（充电检查过压/充电过流；放电检查欠压/放电过流，欠压允许充电恢复），进入充放电前也检查数据；这是额外软件联锁，不代替BMS。阈值和2秒延时需按实物系统确认。

BLE:新增battery_valid；电压仍为vbat但现在是整包mV；cur为32位mA；原temp键改为die_temp，手机解析需同步。屏幕0x2030显示BAT DATA INVALID，SOC数字清零；无效提示不能解释为真实0%电量。电池数据恢复时清该文本区域。

LED由SensorTask串行处理。mod_battery_led_mask(0xFFF)全亮，0全灭，1u<<n单灯(bit0..11=D17..D28)，mod_battery_led_soc恢复SOC。接口返回的是请求被接受，处理结果见快照last_error；单槽邮箱以最新请求为准。12灯固定计数、DNC保留，默认亮度8/31及VLED=2.0V仍需实物核实。

## 学习参数保存

W25Q128第9/10扇区：0x009000..0x00AFFF，共8KiB，专用于电池；避开现有配置0、日志1..8、标定255。未使用MCU内部第11扇区。内部Flash链接长度同时限制为896KiB，防止程序占用已有系统参数区；Keil散布文件同步。此次不烧录、不擦除任何硬件。

64字节记录包含magic/格式版本/序号/配置摘要/电池ID/RComp0/TempCo/FullCapRep/FullCapNom/Cycles/CRC/最后提交字。只选择完整记录；扇区轮换先保留最新有效记录所在扇区。SPI错误不会作为0xFF空白内容接受；写/擦均有回读校验。使用存储互斥锁，未来新增W25Q用户必须通过同一存储层，不可直接并发调用底层驱动。

首次有效采样60秒后建立记录；后续Cycles跨64个原始计数(0.64次)区间且距上次至少60秒保存。正常关机由AppMainTask请求SensorTask保存，最多等待2秒；60秒内已保存则合并请求，不能承诺最后几秒所有学习变化都已写入。突然掉电靠上一条周期记录恢复。写失败保留旧记录并设置BAT_FAULT_NVM。Flash缺失不阻断采样，但有NVM故障。battery_id在更换实物电池时必须改变；配置摘要变化拒绝旧记录。

完整恢复仅在POR发生后进行。MCU单独复位不拿Flash旧记录覆盖芯片当前学习状态。基础LFP模型的学习恢复流程仍需实板掉电验证，不能用仿真证明算法精度。
