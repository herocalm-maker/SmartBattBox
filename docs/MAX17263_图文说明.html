0. 先看懂这张图

MAX17263 只做三件事：量电压（CELLX 分压）、量电流（1mΩ 电阻）、算 SOC（库仑计 + 电压法混合）。它不在电池里，在板子上，所以它看到的是"电池端子节点"的电压——这一点后面会解释很多现象。

图 0-1 系统框图：测量链路 + 通信链路 + 持久化链路

0.1 为什么磷酸铁锂特别难

图 0-2 LFP 平台区：电压几乎不变，SOC 却大幅变化 → 必须靠模型/库仑计

一句话解释

普通锂电（三元）从 3.0V 到 4.2V，电压和电量基本成正比；LFP 在 20%~90% 区间电压只在 3.20~3.35V 之间变化，测量误差 10mV 就能让 SOC 偏 10%。

所以 MAX17263 用两条腿走路：短时间靠库仑计（积分电流），长时间靠电压法 VFG（查 OCV-SOC 曲线）。而曲线准不准，就取决于有没有"电池模型"。

芯片提供"平台区避让窗口"（ScOcvLim，默认 3275~3350mV）：在这个区间内不做 OCV 修正，避免被平台区的微小电压波动带偏。

1. 电池模型（Characterization）

1.1 模型到底是什么

模型就是一组特征化后得到的表格数据，告诉芯片"你这颗电芯在任意温度、任意负载下，电压对应多少电量、内阻多大"。它替换掉 EZ 模式内置的通用曲线。

OCV 表

16 字（80h~8Fh）
+ 16 字 X 表（90h~9Fh）
电压↔SOC 的对应关系

内阻参数

RComp0(38h)、TempCo(39h)、RCompSeg(AFh)
负载下由电压推算 OCV

QR 表

QRTable00/10/20/30
(12h/22h/32h/42h)
不同倍率/温度下的容量修正

关键：模型在芯片里是 RAM。掉电（POR）就没了，每次上电必须重新写进去。

1.6 每次上电都要写吗？—— 是的

图 1-3 芯片 RAM 与 MCU 侧 Flash 的分工

上电装载时序（本项目已实现）

  1. 读 Status，确认 POR=1（芯片真掉电）；等 FStat.DNR=0（约 710ms）
  2. 读 HibCfg 备份 → 写 0x60=0x0090（软唤醒）→ HibCfg=0 → 0x60=0
  3. 写 DesignCap / IChgTerm / VEmpty / FullSOCThr
  4. 写 ModelCfg = 0x0060 | 0x8000（LFP + Refresh）→ 轮询 Refresh 清零
  5. 若有模型：解锁 62h/63h → 写 32 字 → RCompSeg → 上锁 → 容量序列 → QR → optional → Config2|=0x0020(LdMdl) 轮询
  6. 恢复 HibCfg → 清 POR
本项目的 drv_max17263_load_full_model() 已完整实现第 5 步的 ADI Option 3 流程，只差 INI 数据。

2.1 芯片在学什么（学习环路）

图 2-1 三件事：满电学容量、静置学内阻、循环推进学习阶段

2.2 要"打开"哪个寄存器？

不需要额外的"学习使能开关"。MAX17263 上电完成 EZ 配置（ModelCfg.Refresh）后，学习就是自动进行的——只要电池真的经历了"充满 / 放空 / 静置"。

但下面这些寄存器间接决定学习能不能发生、学得准不准：

寄存器本项目值对学习的影响
ModelCfg (DBh)0x0060 + Refresh装载 EZ 模型（LFP 用 ModelID=6）；不 Refresh 就没有正确的算法初始状态
FullSOCThr (13h)0x5005（80%）满电学习的门槛：VFSOC 必须超过它，FQ 才可能置位；设太高（如 95%）EZ 可能永远学不到
IChgTerm (1Eh)0x0080（200mA）配合 FullSOCThr 形成 FQ 电流窗 [0.125, 1.25]×200mA = 25~250mA
VEmpty (3Ah)0x7D4B（2.5/3.0V）空电学习的门槛：电压跌破 VE 触发 EDet，芯片把 SOC 校准到 0
LearnCfg (28h)默认 0x4486（不写）LS 学习阶段：默认自动 0→7；写入 7 可跳过渐进（不建议）
MiscCfg (2Bh)默认 0x3870（不写）FUS 满容量回调斜率（防止 RepSOC 跳变）、MR 混合速率
Config2 (BBh)清 dSOC 中断不影响学习，只影响 ALRT 引脚

2.4 到底读什么、写什么？（回答你的疑问）

不是"读一个寄存器、上电写回一个"。实际是：

掉电前：MCU 读 5 个

寄存器名字
0x38RComp0
0x39TempCo
0x10FullCapRep
0x23FullCapNom
0x17Cycles

上电（POR）后：MCU 写 9 个

寄存器值
0x10 FullCapRep存的值
0x45 dQAccFullCapNom/2
0x46 dPAcc0x0C80
0x23 FullCapNom存的值
0x0F MixCapVFSOC/25600×FullCapNom
0x1F AvCap同上
0x38 RComp0存的值
0x39 TempCo存的值
0x17 Cycles存的值

原因：芯片内部不是"一个数值"，而是容量、累计电量、内阻补偿等一组互相耦合的量；恢复时必须按 ADI 规定的顺序重算 MixCap/AvCap，否则 SOC 会跳。RepSOC(0x06)/RepCap(0x05) 是只读输出，不能直接写。

2.6 不做自学习（或学习失败）的影响

会怎样

  • FullCapRep 永远等于 DesignCap → SOH 恒 100%，容量衰减看不出来
  • 满电点不修正 → SOC 到 100% 的时间点越来越偏
  • 空电点不修正 → 放电末端 SOC 跳变（比如 8% 直接跳到 0%）
  • 长期 SOC 漂移，只能靠断电重启的 OCV 重估纠正

为什么可能学不到（本硬件）

  • 末端净电流 = 充电器电流 − 板载自耗(114mA)，可能掉出 25~250mA 窗口 → FQ 不置位
  • VFSOC 到不了 FullSOCThr（EZ+LFP 平台）→ FQ 不置位
  • 不常放电到 2.5V → 空电学习也很少触发
已用"SOC=100 强停 + 电压/电流 1h 物理兜底"保证充停正确，但注意：FQ 不触发时容量仍然不会学习。
