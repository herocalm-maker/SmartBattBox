# MAX17263 电量计使用现状详细说明

> 更新日期：2026-10-21
> 适用代码：SmartBattBox（STM32F407 + 8串磷酸铁锂 + MAX17263）
> 涉及文件：
> - `BSP/Driver/Src/drv_max17263.c` / `BSP/Driver/Inc/drv_max17263.h` — 芯片驱动（纯逻辑，不依赖 HAL）
> - `Module/Src/mod_battery.c` / `Module/Inc/app_battery.h` — 平台无关电池状态机 + 学习参数持久化 + STM32 任务适配
> - `Module/Inc/battery_config.h` — 板级参数（容量/电阻/阈值/LED）
> - `Module/Src/mod_storage.c` — W25Q128 存储后端挂载
> - `App/Src/app_sensor_task.c` — 唯一调用任务（SensorTask）

---

## 1. 总体架构与数据流

```
SensorTask (20ms 循环)
  └─ mod_battery_handler()                       [Module/Src/mod_battery.c:1197]
       ├─ battery_app_process()                  周期状态机 (3s 采样节拍由内部管理)
       │    ├─ battery_store_load()              启动时读取学习记录 (W25Q128)
       │    ├─ drv_max17263_initialize()         POR 配置 / 暖启动校验
       │    ├─ drv_max17263_sample()             14 个寄存器批量采集 + 换算
       │    ├─ 故障判定 (滞回) + 芯片告警锁存
       │    └─ battery_app_checkpoint()          达到条件时保存学习参数
       ├─ battery_diagnose()                     失效时限频读关键寄存器打印诊断
       ├─ LED 邮箱请求处理 (自定义图案 / SOC 灯条)
       └─ 关机保存邮箱请求处理 (mod_battery_checkpoint)
            └─ publish()                         换算为 BATT_INFO_T 并临界区发布
消费方 (只读 battery_get_snapshot 快照):
  App/Src/app_main_task.c   保护/继电器/显示决策
  App/Src/app_display_task.c DWIN 屏显示
  App/Src/app_ble_task.c    蓝牙上报
  App/Src/app_sensor_task.c 10s 周期日志
```

关键设计约束：

- **单任务独占**：所有 I2C、Flash、LED 操作都收敛到 SensorTask；其他任务只能通过邮箱
  （`mod_battery_led_mask` / `mod_battery_checkpoint`）提交请求。
- **驱动无 HAL 依赖**：`drv_max17263.c` 通过 `max17263_bus_t` 回调（read/write/delay/now）访问
  总线，由 `mod_battery.c` 适配到 `bsp_i2c_hw_*`；地址使用未左移的 7 位值 0x36，
  在适配层左移一次（`mod_battery.c:794`）。
- **快照原子发布**：`publish()` 在 `taskENTER_CRITICAL()` 内整体复制 `BATT_INFO_T`，
  读者不会拿到半新半旧字段。

## 2. 电池模型情况（当前：无特征化模型，EZ 模式）

### 2.1 现状

`battery_config.h:16-22`：

```c
.model = NULL,
.allow_uncharacterized = true,   // 仅台架评估允许
```

- **没有加载任何 ADI 特征化电芯模型**（`max17263_model_t` 的 32 字模型表 / RCompSeg / QR 表均未提供）。
- 驱动走 **EZ 无特征化配置路径**（`drv_max17263_configure()`，`drv_max17263.c:466-502`）：
  1. 读 ModelCfg(0xDB)，保留上电硬件自动检测的拓扑位（bit2..3），置 VSel=1、CSel=1，
     并按 NTC 配置决定 bit13（当前无外部 NTC，不置位）；
  2. 写 DesignCap / IChgTerm / VEmpty / FullSOCThr；
  3. 置 ModelCfg.Refresh（0x8000）触发 EZ 配置，轮询等待自清零；
  4. 写 **ScOcvLim(0xD1) = 0x479E**（磷酸铁锂平台区 keep-out 默认值，对应约 3275~3350mV），
     防止静置 OCV 学习在 LFP 电压平台上误触发。
- 代码注释明确要求：*“Only ADI-characterized values belong here. Never synthesize an OCV table.”*
  —— 即不允许软件伪造 OCV 模型表；要上特征化模型必须来自实际电芯标定。

### 2.2 影响与补偿

| 影响点 | 现状处理 |
|---|---|
| LFP 平台区 SOC 误差大 | ScOcvLim keep-out + FullSOCThr=80% 判满（见 §4.1） |
| 初始 SOC 可能不准 | 新电池且 SOC<5% 时触发 Quick Start（基于 OCV 重估，`mod_battery.c:87-103`） |
| 学习容量依赖库仑积分收敛 | 学习参数持久化 + 每次 POR 恢复（见 §3） |
| 上层知晓模型缺失 | `BAT_WARN_UNCHARACTERIZED` 故障位 + 启动日志 `EZ uncharacterized` |

EZ 模式下芯片内部自动执行 OCV 学习、空电学习、混合学习，无需软件干预；
软件只负责保存/恢复学习结果和参数配置。

## 3. 校准方式（学习参数的采集、持久化与恢复）

MAX17263 本身没有“人工校准”入口，本项目的校准闭环 = **芯片自学习 + 学习参数掉电持久化**。

### 3.1 学习参数（五项）

`max17263_learned_t`（`drv_max17263.h:152`）：

| 字段 | 寄存器 | 含义 |
|---|---|---|
| rcomp0 | RComp0 (0x38) | 静置学习后的内阻补偿基准 |
| tempco | TempCo (0x39) | 内阻温度系数 |
| fullcaprep | FullCapRep (0x10) | 学习后的满容量（报告值） |
| fullcapnom | FullCapNom (0x23) | 标称满容量（滤波值） |
| cycles | Cycles (0x17) | 等效循环次数，0.01 次/LSB |

### 3.2 有效性筛查

`drv_max17263_learned_valid()`（`drv_max17263.c:312-322`）：
五项中两个容量必须落在 `[DesignCap/10, DesignCap×2]` 区间内才认为合理。
**这是损坏筛查而非 SOH 验收标准**——防止 Flash 损坏数据被恢复进芯片。

### 3.3 持久化：W25Q128 双扇区 CRC 日志

存储后端由 `mod_storage.c` 挂载到 **W25Q128 外部 SPI Flash 扇区 9/10**
（`STORAGE_SEC_BATTERY_START=9`，全局地址 0x009000~0x00AFFF，2×4KiB），4KiB/扇区，64B/记录。

64 字节记录格式（`mod_battery.c:709-722`）：

| 偏移 | 内容 |
|---|---|
| 0 | Magic（固定值） |
| 4 | 版本 = 1 |
| 8 | 序号 seq（追加递增，半范围比较处理回绕） |
| 12 | 配置摘要 hash（`battery_profile_hash()`：profile_id、rsense、design_mah、ichgterm、empty/recovery、串数、温度源、模型内容的 FNV 散列） |
| 16 | 电池 ID（换电池时变更） |
| 20~39 | 五项学习参数（各 32 位小端） |
| 56 | CRC32（0xEDB88320，覆盖前 56 字节） |
| 60 | COMMIT 提交标记（**最后写入**） |

写入流程（`battery_store_save()`）：

1. 全扫描两个扇区找最新完整记录 → 确定追加位置；
2. 当前扇区写满 → 轮换到另一扇区并擦除（最新有效记录仍在旧扇区，擦除掉电可恢复）；
3. 先写 60 字节正文并回读比对，**最后**写 4 字节提交标记 —— 半条记录永远不会被误认为有效；
4. 全量回读 + `valid()` 校验。

加载流程（`battery_store_load()`）：按 `hash + battery_id` 双匹配选最新完整记录，
再过 `learned_valid` 容量筛查。换电池或改配置（hash 变化）后旧记录自动失配，
相当于回新电池流程。

### 3.4 保存时机（`battery_app_process`，`mod_battery.c:328-337`）

满足以下全部条件才触发 `battery_app_checkpoint()`：

- 存储后端可用；
- 距上次保存 ≥ **60 秒**（限制 Flash 磨损，失败也计时）；
- 首次建立记录，**或** Cycles 跨过 64 个原始计数区间（= 0.64 次等效循环）。

另外两条独立路径：

- **关机保存**：其他任务调 `mod_battery_checkpoint(timeout_ms)`（邮箱 + 有限等待），
  60 秒内已有记录则合并（`mod_battery.c:1221-1232`）；
- 保存结果异常置 `BAT_FAULT_NVM`，正常则清除。

### 3.5 恢复策略（POR 判定）

`drv_max17263_initialize()`（`drv_max17263.c:512-642`）区分两种情况：

- **POR=1（芯片真掉电）**：软唤醒 → EZ 配置 → 用保存的学习值恢复容量
  （`load_capacity()`：FullCapRep/DQACC/DPACC → FullCapNom → 按 VFSOC 比例重灌 MixCap/AvCap → RComp0/TempCo → Cycles）→ 恢复 HibCfg → 最后清 POR。
- **POR=0（仅 MCU 复位）**：暖启动只做**配置一致性校验**（DesignCap/IChgTerm/VEmpty/
  FullSOCThr/ScOcvLim/ModelCfg/Config 逐项回读比对），不匹配返回 `M_EPROFILE`；
  芯片正在使用的学习结果**不被覆盖**（**不写任何参数**）。

> 注意：MCU 复位不等于电量计复位。固件升级后若改了判满相关参数（需 bump
> `BATTERY_PROFILE_ID`），必须给 MAX17263 完整断电才能重新配置，MCU 单独复位会报
> profile mismatch（诊断日志有明确提示，`mod_battery.c:1184-1188`）。

## 4. 配置参数（写入芯片的完整清单）

配置在初始化时一次性写入，掉电前一直生效。分四组：电量计核心参数、告警阈值、LED 显示、休眠策略。

### 4.1 电量计核心参数（POR 后 EZ 配置序列，`drv_max17263_configure()`）

| 寄存器 | 地址 | 写入原始值 | 来源配置 | 说明 |
|---|---|---|---|---|
| DesignCap | 0x18 | 0x0FA0 (4000) | design_mah=20000, R=1mΩ | 设计容量，raw = mAh×R/5000，串联不乘节数 |
| IChgTerm | 0x1E | 0x0080 (128) | ichgterm_ma=200 | 充电终止电流，raw = mA×R×16/25000 |
| VEmpty | 0x3A | 0x7D4B | empty_mv=2500, recovery_mv=3000 | D15..D7=VE(250，10mV 步进)；D6..D0=VR(75，40mV 步进)，不能按字节拼 |
| FullSOCThr | 0x13 | 0x5005 | full_soc_thr_pct=80 | D15..D8=判满 VFSOC 阈值 80%，低字节固定 0x05；UG6597 p30：EZ 用 80%，特征化模型才用 95% |
| ModelCfg | 0xDB | 保留拓扑位 \| 0x0060 \| Refresh(0x8000) | — | VSel=1/CSel=1；bit2..3 为上电硬件自动检测的多串/电流采样拓扑位，软件保留不覆盖；Refresh 置位后轮询等待自清零 |
| ScOcvLim | 0xD1 | 0x479E | 固定（EZ 路径） | LFP 平台区 keep-out（约 3275~3350mV），防静置 OCV 误学习 |
| Config | 0x1D | 掩码 0x87D8 → 0x0200 | external_ntc=false | Ten=1 用内部 Die 温度，ETHRM=0；清 TSel/Tex/THSH/SHDN/COMMSH/FTHRM |
| HibCfg | 0xBA | 0 → 恢复原值 | — | POR 序列：读出保存 → 软唤醒期间清 0 → 配置完成后恢复原值 |

**模型表 0x80~0x9F、RCompSeg(0xAF)、QR 表(0x12/0x22/0x32/0x42) 均未写**（`model=NULL`，EZ 路径不涉及）。

### 4.2 告警阈值（`drv_max17263_alerts()`，setup 阶段写入）

| 寄存器 | 地址 | 写入原始值 | 来源 | 说明 |
|---|---|---|---|---|
| VALRT | 0x01 | 0xBA7D | 2500/3720mV | D15..D8=上限 186、D7..D0=下限 125（20mV 步进） |
| TALRT | 0x02 | 0x3CEC | -20/60℃ | D15..D8=上限 60、D7..D0=下限 −20（8 位补码） |
| SALRT | 0x03 | 0xFF0A | low_soc=10 | 低 4 位=SOC 下限 10%；高 4 位置 1 表示对应上限类不使能 |
| IALRT | 0xB4 | 0x1997 | 10000/42000mA | D15..D8=充电上限 25、D7..D0=放电下限 −105（raw = mA×R/400000，1mΩ 时步进 400mA；不可精确表示的阈值直接拒绝，不静默取整） |
| Config | 0x1D | 或上 0x7804 | — | V/T/S/I 告警粘滞 + Aen(ALRT 引脚)使能；dSOC 1% 变化中断关闭 |
| Config2 | 0xBB | 清 0x0080 | — | 关 dSOC 中断，减少 IRQ 流量 |

芯片告警只是**锁存信号源**：状态位被读入 `observed_alerts` 并映射到 latched_faults
（UV/OV/OC），软件另有一套带滞回的独立判定（见 §5.2）。

### 4.3 LED 显示配置（`drv_max17263_led()`）

| 寄存器 | 地址 | 写入原始值 | 来源 |
|---|---|---|---|
| LEDCfg1 | 0x40 | 0x8CDC | mode=3（持续显示）、NBARS=12、分组设置 |
| LEDCfg2 | 0x4B | 0x6448 | VLED=2000mV（50×40mV）、手动灯数、空电闪烁、亮度 8 |
| LEDCfg3 | 0x37 | 或上 0x8000 | 保留 DNC(bit14) |

另有 12 灯自定义图案接口（`drv_max17263_led_mask/led_set`）：先预写 CustLED(0x64)
再切模式（LEDCfg1→0x00CC、LEDCfg3→0xA000），供 App 层做告警/呼吸图案；恢复自动 SOC

### 4.4 应用策略 `battery_policy`（`battery_config.h:23-29`，软件判定用，不直接写芯片）

| 参数 | 值 | 用途 |
|---|---|---|
| min/max_cell_mv | 2500 / 3720 | 软件滞回故障（同时是 VALRT 来源） |
| min/max_temp_c | -20 / 60 | 软件滞回（同时是 TALRT 来源） |
| low_soc | 10 | 软件滞回（同时是 SALRT 来源） |
| max_discharge_ma | 42000 | 软件过流（同时是 IALRT 来源） |
| max_charge_ma | 10000 | 软件过流（同时是 IALRT 来源） |
| period_ms | 3000 | 采样周期；初始化失败按 5s 退避重试 |
| stale_ms | 3500 | 数据有效期（≈1 个采样周期） |
| led_bars/mode/brightness/led_mv | 12 / 3 / 8 / 2000 | 自动 SOC 灯条常显 |

`BATTERY_TAPER_MA=500`（`battery_config.h:12-13`）；判满优先级：FStat.FQ 位 → 应用层兜底。

### 4.5 配置生效与校验方式

- **读重试、写不重试**：读失败重试 3 次（间隔 2ms）；写失败不盲目重试（避免命令重复生效），
  配置类写入用回读校验（`drv_max17263_write_verify()`，3 次尝试）保证真正生效。
- **暖启动（POR=0，仅 MCU 复位）不写任何参数**：只回读 DesignCap/IChgTerm/VEmpty/
  FullSOCThr/ScOcvLim/ModelCfg/Config 逐项比对，不匹配报 `M_EPROFILE`——
  目的是不覆盖芯片正在使用的学习结果（见 §3.5）。

## 5. 采集的数据（读取清单）

读回分三条独立路径：周期采样、学习参数检查点、故障诊断。

### 5.1 周期采样（`drv_max17263_sample()`，每 3s 一次）

顺序读 14 个寄存器 + 复读 STATUS + 读 FSTAT：

| # | 寄存器 | 地址 | 换算后字段（1mΩ/8S） | 换算公式 |
|---|---|---|---|---|
| 1 | STATUS | 0x00 | status | POR/告警位图，读前后各查一次 |
| 2 | VCell | 0x09 | cell_mv | raw × 0.078125 mV（**等效单体**，非逐节测量） |
| 3 | AvgVCell | 0x19 | avg_cell_mv | raw × 0.078125 mV |
| 4 | Current | 0x0A | current_ma | 有符号 × 1.5625 mA，充电为正 |
| 5 | AvgCurrent | 0x0B | avg_current_ma | 有符号 × 1.5625 mA |
| 6 | Temp | 0x08 | temp_c | 有符号 / 256 ℃（**芯片 Die 温度，不代表电芯温度**） |
| 7 | RepSOC | 0x06 | soc_pct | raw / 256 %（对外显示口径） |
| 8 | RepCap | 0x05 | remaining_mah | raw × 5 mAh（容量 LSB = 5µVh/Rsense） |
| 9 | FullCapRep | 0x10 | full_mah | raw × 5 mAh |
| 10 | FullCapNom | 0x23 | nominal_full_mah | raw × 5 mAh |
| 11 | Cycles | 0x17 | cycles / cycles_raw | raw / 100 次；≥65000 置 `BAT_WARN_CYCLE_RANGE` 维护提示 |
| 12 | TTE | 0x11 | tte_s | raw × 5.625 s（**已弃用**，应用层自算，见 §5.2） |
| 13 | TTF | 0x20 | ttf_s | raw × 5.625 s（已弃用） |
| 14 | VFSOC | 0xFF | vfsoc_pct | raw / 256 %（FQ 判满看 VFSOC，不看 RepSOC） |
| — | STATUS 复读 | 0x00 | — | 与首读合并；任一次 POR 置位则整轮作废（`M_EPOR`） |
| — | FStat | 0x3D | 三个状态位 | DNR=1 → `M_ENOTREADY` |

软件派生量（不发 I2C）：

- `pack_mv` = cell_mv × 8（推算值，非独立测量）
- `soh_capacity_pct` = FullCapRep / DesignCap × 100
- FStat 解析：`full_qualified`（FQ, bit5, 充满确认）、`empty_detected`（EDet, bit3）、
  `relaxed`（ReIDt, bit6, 静置检测，**不是满电标志**）

**完整性门槛**（任一失败整快照 `valid=false`）：POR 前后双查为 0、DNR=0、
单体 1500~4500mV、温度 -40~85℃、SOC/VFSOC ≤100.5%、两个容量寄存器非零、
电流非 0x8000/0x7FFF ADC 饱和、外部 NTC 配置下 BST=0（当前不适用）。

### 5.2 应用层再加工（`publish()`，`mod_battery.c:994-1093`）

- **TTE/TTF 自算**（不再用芯片寄存器）：TTE = RepCap/|AvgCurrent|，
  TTF = (FullCapRep−RepCap)/AvgCurrent；方向用平均电流 ±50mA 死区判定
  （瞬时电流过零毛刺不翻转有效标志）；两级滤波 = 10 样本中值（~30s 窗）→ 0.35
  一阶低通；方向翻转即新会话，滤波器复位首采直通。仅显示用，保护仍用原值。
- **故障体系**：
  - `active_faults`：带滞回的实时判定（电压 80mV、温度 2℃、电流回阈值 90%、SOC 回升 2%）；
  - `latched_faults`：历史锁存，UV/OV/OC 由芯片 Status 告警位触发；
  - `observed_alerts`：两次采样间的短时告警事件，`ack_alerts()` 按 W0C（写 0 清除）语义确认。
  - 完整故障位定义见 `app_battery.h:60-77`。
- **告警折叠 `fold_alarm()`**：I2C 连续失败 ≥10 次（约 30s）才报 `SYS_ALARM_BAT_COMM`；
  Die 温度 HOT/COLD **不**折叠为电芯过温保护（电芯过温以 mod_temp 独立 NTC 为准）；
  `BAT_FAULT_SENSOR` → `SYS_ALARM_BAT_INVALID`。

### 5.3 学习参数检查点（`drv_max17263_get_learned()`，保存前读）

| 寄存器 | 地址 | 存入 W25Q128 记录的偏移 |
|---|---|---|
| RComp0 | 0x38 | +20 |
| TempCo | 0x39 | +24 |
| FullCapRep | 0x10 | +28 |
| FullCapNom | 0x23 | +32 |
| Cycles | 0x17 | +36 |

读前后查 POR、查 FStat.DNR，并过容量合理性筛查（DesignCap/10 ~ ×2）后才写 Flash。

### 5.4 故障诊断读（`battery_diagnose()`，数据失效时限频打印，只读）

`DevName(0x21), Status, FStat, ModelCfg, Config, DesignCap, IChgTerm, VEmpty, HibCfg,
VCell, Current, Temp, RepSOC, FullCapRep, FullCapNom, LEDCfg1/2/3` —— 共 18 个寄存器，
与期望值对照定位是配置丢失、I2C 故障还是芯片复位。诊断读使用驱动**副本**（probe），
失败不影响原始错误上下文（`mod_battery.c:1160`）。

### 5.5 对外数据结构 `BATT_INFO_T`

发布字段：valid/online、电压（包/单体/平均）、电流（瞬时/平均）、温度(0.1℃)、
soc、vfsoc、soh、repcap_mah、fullcap_mah、cycles_raw、tte/ttf（分钟+有效标志）、
full_qualified、fstat_raw、故障三联位图（active/latched/observed）、last_error、alert_flags。
消费方见 §1；另有 10s 周期串口日志（`app_sensor_task.c:42-88`）。

## 6. 局限与注意事项（现状已知边界）

1. **无特征化模型**：EZ 模式在 LFP 平台区（~3.2~3.3V）SOC 误差可达数个百分点，
   依赖 FullSOCThr=80% + ScOcvLim keep-out + 应用层判满兜底缓解。
   正式量产前应对实际电芯做 ADI 特征化并填入 `max17263_model_t`（含 optional 白名单寄存器），
   同时 bump `BATTERY_PROFILE_ID`。
2. **温度源是芯片 Die 温度**：与电芯实际温度可能偏差较大，仅用于电量计内部补偿和粗略告警，
   电芯保护必须走 mod_temp 的独立 NTC。
3. **整包电压是推算值**（等效单体 × 8）：无逐节电压测量，压差/单体故障检测不在本芯片能力内。
4. **VEmpty=2500/3000mV 沿用既有工程值**，非特征化结果（`battery_config.h:1-3` 注释明示）；
   判满/过压口径已按实测充电器 CV=29.2V（3.65V/节）修正为 3650mV/3720mV（PROFILE_ID=6）。
5. **profile 变更需芯片断电**：改 `battery_cfg` 中参与 hash 的任何参数后，须 bump
   `BATTERY_PROFILE_ID` 并给 MAX17263 完整断电（MCU 复位不够，见 §3.5）。
6. **写操作不重试**：读失败重试 3 次（间隔 2ms），写失败不盲目重试（避免命令重复生效），
   配置类写入用回读校验（`write_verify`）保证生效。
