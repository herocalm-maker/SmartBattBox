## 一、充电启动条件

`need_charge` 置 1 需要**同时满足**以下前提：

| 前提 | 说明 |
|---|---|
| `mode == CHARGE_BYPASS` | 有 220V（市电在位） |
| AC 稳定 ≥ 2s | `AC_STABLE_MS` |
| 不在停充冷却期 | `CHARGE_RESTART_BLOCK_MS`（10min）；AC 拔插可立即解除 |
| 电池数据有效 | `battery_get_snapshot()` 成功 |
| 电池未过温 | `< 60℃`（`bat_otp == false`） |
| 物理满锁存为 0 | `s_phys_full == false` |

**并且**满足下列**任一**条件：

1. **来电补满窗口内** —— AC 掉电恢复后的 10 分钟内（`AC_BACK_TOPUP_MS`；
   任何"非 PRESENT → PRESENT"都算回电，包括 UNKNOWN→PRESENT），
   无论 SOC / 电压多少都充；窗口被消费一次后失效。
2. **平时双条件** —— `SOC ≤ 97%` **且** 整包电压已进入低位区（迟滞：
   `< 27.16V` 进入 / `> 27.24V` 退出）。

## 二、停充条件

| 路径 | 条件 | 动作 |
|---|---|---|
| **A1** | SOC=100% **且** FQ=1 **且** TTF=0 | 立即停 |
| **A2** | SOC=100% 但 FQ / TTF 未同时满足 | `CHARGE_FULL_FORCE_MS` = **5min** 后强制停 |
| **B（物理兜底）** | SOC<100%，单体 ≥3600mV(28.8V) 且 \|avgI\| ≤500mA **持续 1h** | 停充 + **置物理满锁存** |
| 拔电 | 充电中 220V 丢失（mode 切 INVERT） | 立即停 |
| 过温 | 电池 ≥60℃ | 停充 + 停输出 |
| 保护 | OVP / UVP / OCP 等电池保护 | 停充 + 报错 |

> B 路径刻意**不要求 TTF=0**：本工程 TTF=0 与 SOC=100 等价，加上后 B 永远无法触发。
> 适用场景：库仑计 SOC 到不了 100%（容量学习偏差、电池老化、EZ 模式）。

## 三、停充之后

```
charge_full = true（屏显示"满"）
        ↓
10 分钟冷却（CHARGE_RESTART_BLOCK_MS），期间不启动
        ↓
冷却到期  或  AC 拔插  →  解除
        ↓
下次启动时清 charge_full 锁存（"BAT full latch cleared at charge start"）
```

**物理满锁存 `s_phys_full`**（仅 B 路径置位）额外要求：

- `SOC < 95%`（`CHARGE_FULL_PHYS_REARM_SOC`）**或**
- AC 拔插

才能解除。

## 六、为什么要改成双条件（背景）

2026-11-20 18:35~19:49 充电日志暴露的问题：

```
18:59:48  停充（SOC=100%，latch=1，blk=600s）
19:14:29  need=1 soc=99  → CHG_IN ON → 充 3 秒
19:14:32  need=0 soc=100 → 停
19:16:49  need=1 soc=99  → 又充 3 秒 → 停
19:28:50  need=1 soc=99  → 再充
```

**1 小时 15 分内充电器启停 4 次，其中 3 次只充 2~3 秒。**

根因：

1. 停充后电池电压弛豫，库仑计按 OCV 重算 SOC → 100% 掉到 99%
2. 旧门限 `CHARGE_RESTART_SOC = 100`，`SOC < 100` 就允许充电 → 立刻补电
3. 补电几秒又回 100% → 停 → 10min 后再来一遍

LFP 的 OCV-SOC 曲线在 20%~90% 之间极平坦（3.30~3.35V），单靠电压估 SOC 不可靠，
但用它做"是否真的离开满电平台"的**迟滞判据**是可靠的 —— 这就是 27.16V / 27.24V 的由来。

本机实测（同日日志）：

| 时刻 | 整包电压 | 单体 |
|---|---|---|
| 充电中（CV） | 29 226 mV | 3653 mV |
| 停充后 1min | 28 519 mV | 3565 mV |
| 停充后 15min | 28 032 mV | 3504 mV |
| 停充后 45min | 27 750 mV | 3469 mV |

→ 满电静置约 3.47~3.55V/单体，取 **3.40V/单体** 作为补电门限，
按 100mA 自耗估算约 **8~12 小时**才会补一次电。

## 七、验证方法

插着 220V 放一夜，次日抓串口日志核对：

1. `CHG: stopped` 之后**不应再出现** `CHG_IN ON`（除了 AC 拔插）
2. `auto chg:` 行可看到完整判定输入：

```
auto chg: need=%d ok=%d soc=%u vol=%umV vlow=%d acback=%d fq=%d fb=%d
```

3. 拔掉再插上 220V，应看到：

```
auto chg: AC state=0
auto chg: AC state=1
auto chg: restart block cleared (AC re-inserted)
auto chg: need=1 ok=1 soc=99 vol=28400mV vlow=0 acback=1 fq=0 fb=0
CHG: CHG_IN ON, start 1500ms
```

4. 判满停充的完整序列应为：

```
BAT FULL (FQ+TTF): soc=100% fq=1 ttf=0min vfsoc=99% avgI=39mA cellAvg=3654mV, block 600s
CHG: stopped
[BAT] mode: CHARGE_BYPASS, chg: IDLE, need: 0, blk: 596s, full: fq=1 latch=1 app=1
```

5. 停充后 `need` 必须保持 0（除非 AC 拔插），且 `vlow` 在电压回到 27.24V 以上时变 0。

## 八、2026-11-21 修订（两处边界缺陷）

依据 `QCOM_LOG1120-充电过程-2.txt`（2026-11-20 20:26~20:44）的核对结果：

### 8.1 电压门限加迟滞

**问题**：旧实现是单点阈值 `voltage < 27200`，而采样噪声约 ±15mV：

```
20:28:16  need=0  vol=27213mV
20:28:22  need=1  vol=27196mV     ← 仅低 4mV
20:28:25  need=0  vol=27214mV     ← 仅高 14mV
```

9 秒内 need 翻转两次。本次因为已经在充电（`need` 只负责启动）没有造成危害，
但若处于 IDLE 状态，会变成"启动→撤销→启动"的继电器抖动。

**改法**：

```c
#define CHARGE_RESTART_V_ENTER_MV  27160u   /* < 27.16V 进入低位区 */
#define CHARGE_RESTART_V_EXIT_MV   27240u   /* > 27.24V 退出低位区 */

static bool s_v_low;    /* 迟滞状态 */
if (voltage_mv < ENTER)      s_v_low = true;
else if (voltage_mv > EXIT)  s_v_low = false;
need_charge = ... && (ac_came_back || (soc <= 97 && s_v_low)) && ...
```

迟滞带 80mV。

### 8.2 物理兜底 1h 计时加容错

**问题**：原实现只要**一拍**不满足就清零计时：

```c
if (!phys_ok) { s_phys_pending = false; return; }
```

实测日志里同一段 2 分钟内出现 **5 次**计时重启：

```
20:38:06  phys full in 3600s
20:38:30  phys full in 3600s     ← 清零重启
20:39:00  phys full in 3600s     ← 清零重启
20:39:37  phys full in 3600s     ← 清零重启
20:40:22  phys full in 3600s     ← 清零重启
```

触发源是充电器二次 bulk 时的电流尖峰（`cur=6138mA / avgcur=859mA` > 500mA）。
若某台设备 SOC 到不了 100%（正是 B 路径存在的意义），这种周期性尖峰会让
**1h 计时永远无法完成** → 永远判不满。

**改法**：连续不满足 10s 才作废计时

```c
#define PHYS_BREAK_TOLERANCE_MS  10000u

if (!phys_ok) {
    if (s_phys_break_since == 0u)            s_phys_break_since = now;
    else if (now - s_phys_break_since >= 10s) { s_phys_break_since = 0u; s_phys_pending = false; }
    return;
}
s_phys_break_since = 0u;    /* 恢复即清零中断计时 */
```

### 8.6 2026-11-22 补充：来电补满失效修复 + 兜底容错加长

依据 `QCOM_LOG1122-充电.txt`（11-21 20:09 → 11-22 16:59）核对：

**问题 A：来电补满从未生效**

```
12:30:06  AC state=0 (UNKNOWN)
12:30:07  AC state=2 (PRESENT)
12:30:09  auto chg: need=1 soc=3 vol=23429mV vlow=1 acback=0   ← 应为 1

13:38:00  AC state=0 (UNKNOWN)
13:38:01  AC state=2 (PRESENT)
13:38:03  auto chg: need=1 soc=21 vol=26239mV vlow=1 acback=0  ← 应为 1
```

原判定 `(s_ac_prev == ABSENT && ac == PRESENT)` 太严：HLW8110 在 VIN=0 时先报
UNKNOWN(0) 再报 ABSENT(1)，实际插电走的是 **UNKNOWN → PRESENT**，边沿永远不成立。

**改法**：

```c
bool ac_recycle = (ac == AC_INPUT_PRESENT) &&
                  (s_ac_prev != AC_INPUT_PRESENT) &&
                  s_ac_had_present;   /* 冷启动首次 PRESENT 不算回电 */
```

**问题 B：物理兜底 1h 计时仍被清零**

```
16:45:54  phys full in 3600s
16:46:24  phys full in 3600s   ← 30s 后又重启
16:46:54  phys full in 3600s   ← 又重启
```

taper 段 `avgI` 在 500mA 门限附近抖动，10s 容错不够。

**改法**：`PHYS_BREAK_TOLERANCE_MS` 10 000 → **120 000**（2 分钟）。
