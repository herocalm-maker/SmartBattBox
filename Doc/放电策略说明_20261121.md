## 一、启动条件（逆变输出）

手动按 AC OUT 或 220V 掉电自动转逆变，**必须同时满足**：

| 条件 | 说明 |
|---|---|
| `mode == WORK_MODE_INVERT` | 无市电（旁路不走本流程） |
| `ac_out_requested == true` | 用户请求（或 220V 掉电时保持的请求） |
| **SOC ≥ 1%** | `INV_MIN_SOC_PCT` |
| **单体 ≥ 3.00V** | `INV_CELL_RESUME_MV`（欠压未恢复则拒绝） |
| 电池数据有效 | `battery_get_snapshot()` 成功 |
| 无故障 | `fault_active == false` |

拒绝时：3 声蜂鸣 + 日志，**不刷 ERR 码**（按产品需求）。

```
INV start rejected: soc=12% (<1%) cell=2830mV (<3000mV), beep 3
```

## 二、启动时序

```
PD4 吸合（预充电阻限流给母线电容充电）
   ↓ 1.5s            PATH_PRECHARGE_MS
PD7 吸合（主继电器）
   ↓ 0.5s            PATH_DC_FAST_MS
PD4 断开（电池直连，撤掉预充电阻）
   ↓ 1.5s            PATH_INVERTER_START_MS
PD0 吸合（输出接通）
```

**共 3.5 秒**。每一步都打日志：

```
INV: PD4 ON, precharge 1500ms
INV: PD7 ON, wait 500ms
INV: PD4 OFF (direct), wait 1500ms
INV: PD0 ON, running
```

## 三、运行中的保护（按优先级）

### 3.1 三级欠压 / 低电量（2026-11-21 新增）

| 优先级 | 条件 | 动作 | 恢复 |
|---|---|---|---|
| **1** | 单体 ≤ **2.70V** | 立即关输出 + **锁存**（`LOG_ERROR`） | 单体 ≥ 3.00V 自动解除 |
| **2** | 单体 ≤ **2.80V** | 关输出 + 3 声蜂鸣（`LOG_WARN`） | 单体 ≥ 3.00V **且冷却 2min 后**可再开 |
| 3 | SOC < 1% | 关输出 + 3 声蜂鸣 | SOC ≥ 1% 可重新开启 |

```
INV: cell=2785mV <= 2800mV (soft UV), output off, beep 3
INV: cell=2698mV <= 2700mV (hard UV), output off & latched, beep 3
INV: UV hard latch cleared (cell=3012mV >= 3000mV)
```

**为什么是 2.8V / 2.7V**：LFP 满电静置约 3.35~3.45V/单体，2.8V 已进入曲线陡降段，
2.7V 接近厂商截止电压（2.5V）的安全裕度上限。详见第八章实测证据。

### 3.2 过载保护

| 门限 | 动作 | 计时 |
|---|---|---|
| **> 500W** | 声光报警（蜂鸣 2s 周期 + 报警灯 + 屏 `OVERLOAD` 闪烁） | 立即 |
| **> 700W** | 停输出（`output off (overload)`） | 持续 **30s** |
| **> 1000W** | 立即停输出（`output off (hard)`） | 持续 **3s** |

回落即清零计时。判据用**原始瞬时功率** `vout_p_w`（非滤波值），保证响应速度。

### 3.3 其它保护

| 项目 | 门限 | 动作 |
|---|---|---|
| 电池过温 | NTC ≥ **60℃** | 停充电 + 停交流输出 + 3 声蜂鸣 |
| 电池过温解除 | NTC ≤ **55℃** | 自动恢复 |
| 逆变器过温 | ≥ 75℃（预警 60℃） | 故障跳闸 |
| 输出通道失效 | 计量无数据 `out_ok == false` | 立即停输出 + 2 声蜂鸣 |
| 空载自动关 | 输出功率 ≤ 1W 持续 **50min** | 关输出（`AC_IDLE_STOP_MS`） |

## 四、停止时序

```
PD0 断开
   ↓ 1.5s
PD7 + PD4 断开（电池与逆变器完全隔离）
```

日志：`INV: PD0 OFF, stopping` → `INV: stopped`

## 五、场景行为矩阵

| # | 场景 | 条件 | 行为 |
|---|---|---|---|
| 1 | 冷启动、无市电、按 AC OUT | SOC 80%、3.30V/单体 | ✅ 启动 |

| 4 | 带 440W 负载 | <500W | ✅ 正常运行，无报警 |
| 5 | 带 600W 负载 | >500W | ⚠️ 声光报警 + `OVERLOAD`，**不停机** |

## 八、2026-11-21 修订记录（欠压保护）

### 8.1 问题

`QCOM_LOG1121-放电.txt`（2026-11-21 15:58→18:06，2 小时 04 分）实测：

```
17:29:55  SOC 1%  整包 24.87V  (3.11V/单体)  延续放电
17:39:09  SOC 1%  整包 23.01V  (2.88V/单体)
17:48:12  SOC 1%  整包 21.12V  (2.64V/单体)
17:57:15  SOC 1%  整包 20.67V  (2.58V/单体)  ← 严重过放
18:05:07  SOC 0%  → 才靠低电量逻辑关断
```

**根因**：生效的欠压门限是 `battery_policy.min_cell_mv = 2500`（整包 20.0V），
而 `project_param.bat_uvp_mv = 24000` **从未被任何代码读取**（死参数）。

LFP 单体 2.58V 已进入深度过放区，长期如此会造成不可逆容量损失。

### 8.2 改法

在应用层（逆变通路）新增三级判定，**不动** `min_cell_mv`（保留 2.5V 作为库仑计层面的
最后冗余，避免影响充电恢复逻辑）：

```c
#define INV_CELL_SOFT_MV     2800u   /* 软停 */
#define INV_CELL_HARD_MV     2700u   /* 硬停 */
#define INV_CELL_RESUME_MV   3000u   /* 解除 / 重启门限 */
```

- 运行时：硬停 > 软停 > SOC<1% 三级优先
- 启动入口 `invert_soc_allow()`：单体 <3.00V 直接拒绝（含 220V 掉电自动转逆变）
- 硬停锁存：单体回到 3.00V 自动解除并打日志

### 8.4 验证方法

烧新固件后做放电测试，关注：

1. 电压降到 **22.4V（2.80V/单体）** 时应出现：

```
INV: cell=2798mV <= 2800mV (soft UV), output off, beep 3
INV: PD0 OFF, stopping
```

2. 此时按 AC OUT 再开，应被拒绝：

```
INV start rejected: soc=1% (<1%) cell=2801mV (<3000mV), beep 3
```

3. 接 220V 充一会儿，单体回到 3.00V 以上、且 2 分钟冷却已过后才能正常启动。

### 8.5 2026-11-21 补充：恢复门限 3.00V + 2 分钟冷却 + LOWBAT 显示

`QCOM_LOG1121-放电-2.txt` 实测暴露"开-停循环"：

```
19:15:10  软停（cell=2793mV）
19:15–19:23  静置 8min，电压回弹到 24.25V = 3.03V/单体
19:23:07  按 ON → 3.03V ≥ 2.85V，允许启动
19:23:19  带载 25A → 2.91V/单体
19:23:49  带载 25A → 2.81V/单体
19:23:54  软停（cell=2788mV）    ← 只撑了 47 秒
19:24:04  再开 → 19:24:18 又软停 ← 只撑了 14 秒
```

**根因**：实测内阻 8.9mΩ/单体（71mΩ/包），25A 时 IR 压降 **0.224V/单体**。
恢复门限 2.85V 落在"静置能过、带载必跌"的区间：

| 静置电压 | 带载 25A 后 | 结果 |
|---|---|---|
| 3.03V | 2.81V | 软停（实测） |
| 2.85V | **2.63V** | 会直接击穿 2.70V → 硬停锁存 |

**改法**：

```c
#define INV_CELL_RESUME_MV       3000u   /* 2850 → 3000 */
#define INV_UV_RESTART_HOLD_MS   120000u /* 停输出后 2 分钟内拒绝重启 */
```

- 恢复门限 3.00V：带载后跌到 ~2.78V，仍在软停区，不会击穿硬停
- 2 分钟冷却：最坏情况是"每 2 分钟才能试一次"，不再 14 秒一次反复吸合继电器
- 冷却在开始充电时立即解除

**屏显 `LOWBAT`**：

| 项 | 说明 |
|---|---|
| 控件 | TextAlarm `0x2060`（8 字符） |
| 内容优先级 | `LOWBAT` > `OVERLOAD` > 空 |
| 显示方式 | **2.0s 周期闪动**（亮 1s / 灭 1s），与 OVERLOAD 同相、与蜂鸣器/报警灯同步 |
| 置位 | 软停 / 硬停 / SOC<1% 停输出 |
| 清除 | 开始充电，或逆变重新进入 RUNNING |

接口：`app_ui_lowbat()`（[app_main_task.h](../App/Inc/app_main_task.h)）

冷却期拒绝启动的日志：

```
INV start rejected: UV cooldown 96s left, beep 3
```
