# 移动电池逆变器 — 软件架构设计

> 目标平台：STM32F407VGT6（Cortex-M4F，168MHz，1MB Flash / 192KB RAM）
> 内核：FreeRTOS V10.3.1 + CMSIS-RTOS v2
> HAL：STM32F4xx HAL Driver
> 工程现状：CubeMX 已生成外设初始化（GPIO/DMA/ADC1/I2C1/SPI2/UART1/2/3/4/6/IWDG/TIM4），仅含 `defaultTask` 空壳，业务代码待实现。
> 设计原则：**分层 + 模块化 + 任务隔离 + 接口向下隐藏硬件、向上提供业务能力**

---

## 一、分层架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  L5  应用层 App Layer        —— 状态机、业务编排、保护策略    │
│      (PowerManage / InvControl / ChargeManage / Protect)     │
├─────────────────────────────────────────────────────────────┤
│  L4  服务层 Service Layer    —— 跨模块协调、事件分发、存储   │
│      (EventBus / StateManager / ConfigStore / LogService)    │
├─────────────────────────────────────────────────────────────┤
│  L3  模块层 Module Layer     —— 功能聚合（设备对象）          │
│      (Battery / Metering / AcSwitch / Display / Ble / Keys)  │
├─────────────────────────────────────────────────────────────┤
│  L2  驱动层 Driver Layer     —— 芯片级驱动（每颗 IC 一个 .c） │
│      (HLW8110 / MAX17263 / W25Q128 / PB03F / PC817 / TPS5430)│
├─────────────────────────────────────────────────────────────┤
│  L1  硬件抽象层 BSP / HAL    —— CubeMX 生成 + IO 映射封装     │
│      (gpio / adc / i2c / spi / usart / tim / dma / iwdg)     │
├─────────────────────────────────────────────────────────────┤
│  L0  RTOS / CMSIS            —— FreeRTOS、CMSIS-RTOS v2      │
└─────────────────────────────────────────────────────────────┘
```

**依赖规则**：上层只调用下层；同层之间不直接调用，需经服务层；驱动层不直接调用应用层。所有跨层通信通过 `xxx_api.h` 暴露的接口完成，便于替换底层实现。

## 四、FreeRTOS 任务设计

| 任务名 | 优先级 | 栈/4B | 周期/触发 | 职责 | 所属层 |
|---|---|---|---|---|---|
| TaskState | High (7) | 512 | 事件触发 | 系统主状态机：OFF→BOOT→IDLE→CHARGE/INVERT/BYPASS→SHUTDOWN | L5 |
| TaskProtect | AboveHigh (8) | 256 | 50ms 周期 + 事件 | 过压/过流/过温/低SoC 检测，触发即切断强电 | L5 |
| TaskPower | High (7) | 256 | 事件 | 开关机时序：上电使能→等待各路电源就绪→LDO 通断 | L5 |
| TaskInv | Normal (5) | 512 | 事件/状态 | 逆变器启停时序：吸合接触器→等待预充→允许逆变输出 | L5 |
| TaskCharge | Normal (5) | 384 | 事件 | 充电流程：识别输入→闭合 CHG_IN/CHG_OUT→监控 | L5 |
| TaskMetering | Normal (5) | 256 | 200ms 周期 | 轮询 HLW8110 输入/输出电参数 → 写共享数据 | L3 |
| TaskBattery | Normal (5) | 256 | 1s 周期 + ALRT 事件 | 读取 MAX17263 SOC/电压/电流/温度 | L3 |
| TaskHmi | BelowNormal (3) | 256 | 20ms 周期 | 按键/编码器扫描去抖，LED/蜂鸣器刷新 | L3 |
| TaskDisplay | Low (2) | 384 | 100ms 周期 | 串口屏页面刷新 | L3 |
| TaskBle | Low (2) | 256 | UART RX 阻塞 | 蓝牙收发与协议解析 | L3 |
| TaskStorage | Low (2) | 512 | 事件 | Flash 读写（参数/日志），保证掉电安全 | L4 |
| TaskComm | Low (2) | 256 | UART RX 阻塞 | UART1 调试命令行 | L4 |
| TaskWatchdog | Idle (1) | 128 | 1s 周期 | IWDG 喂狗 + 任务心跳检查 | L1 |

**任务模型**：周期任务用 `osDelayUntil`；事件任务用 `osMessageQueueGet` 阻塞；中断通过 `osThreadFlagsSet` / `osSemaphoreRelease` 唤醒任务。**所有强电控制只在 TaskState/TaskProtect/TaskInv/TaskCharge 中执行，禁止在 ISR 中直接动作继电器。**

## 五、跨任务通信设计

| 机制 | 用途 |
|---|---|
| `osMessageQueue` | 事件总线（svc_eventbus）：状态变化、报警、按键、计量更新 |
| `osMutex` | 保护 I2C1（电池+其他）、SPI2（Flash）、共享数据结构 |
| `osThreadFlags` | ISR → 任务快速唤醒（HLW8110 UART Rx、MAX17263 ALRT、按键 EXTI） |
| `osEventFlags` | 跨任务同步：电源就绪、Flash 操作完成、保护解除 |
| `osTimer` (Software) | 软定时器：长按判定、报警去抖、自熄 LED |

**共享数据**：电池/计量数据封装为只读快照结构体 `BatterySnapshot_t`、`MeterSnapshot_t`，由拥有任务用 mutex 写、其他任务无锁读（双缓冲），避免竞争。


### 2. mod_metering (L3)

```c
void mod_metering_init(void);
```

### 3. mod_acswitch (L3) — AC 五路通断
```c
typedef enum { AC_CHG_IN, AC_CHG_OUT, AC_BYPASS, AC_INV_IN, AC_INV_OUT } ac_path_t;

/* 能量通路（受互锁约束，任一时刻仅一条主通路激活） */
typedef enum {
    PATH_NONE,        /* 全断开 */
    PATH_BYPASS,      /* AC 直通：AC_IN → AC_CTRL → AC_OUT   (仅 AC 接入时) */
    PATH_CHARGE,      /* 充电：  AC_IN → CHG_IN → 充电器 → CHG_OUT → 电池 (仅 AC 接入时) */
    PATH_INVERT       /* 逆变：  电池 → 接触器 → 逆变器 → INV_OUT → AC_OUT (仅 AC 未接入时) */
} energy_path_t;

bool mod_acswitch_on (ac_path_t p);
bool mod_acswitch_off(ac_path_t p);
bool mod_acswitch_state(ac_path_t p);   /* 当前吸合状态 */

/* 通路级互锁：申请切换到新通路，内部保证先断后通、互斥切换 */
bool mod_acswitch_select_path(energy_path_t path);
energy_path_t mod_acswitch_current_path(void);
```

**互锁规则**（在驱动内强制，应用层不可绕过）：
- `PATH_BYPASS` 与 `PATH_CHARGE` 互斥：AC 接入时二选一，切换需先全断再吸合新通路
- `PATH_INVERT` 与 `PATH_BYPASS`/`PATH_CHARGE` 互斥：AC 接入时禁止进入逆变
- 任一通路切换均为 "先断 → 死区延时(≥50ms) → 再通"，避免跨通路短路

### 4. svc_state (L4) — 系统状态机

```c
typedef enum {
    ST_OFF, ST_BOOT, ST_STANDBY,
    ST_CHARGING, ST_INVERTING, ST_BYPASS,
    ST_FAULT, ST_SHUTDOWN

void svc_state_transition(sys_event_t evt);   // 线程安全
sys_state_t svc_state_current(void);
```

### 5. svc_config (L4) — 参数持久化
```c
typedef struct {
    uint32_t magic;

    int16_t  otp_deg, utp_deg;

    /* AC 通路判定与互锁参数 */
    uint16_t ac_in_present_v;     /* AC 接入判定阈值，默认 180V */
    uint16_t ac_in_absent_v;      /* AC 断开判定阈值，默认 50V（迟滞） */

    uint8_t  default_path_on_ac;  /* AC 接入时默认通路：0=BYPASS 1=CHARGE */
    // ...
} config_t;
bool svc_config_load (config_t *out);
bool svc_config_save (const config_t *in);
```

## 七、状态机概览（L5 app 层）

```
        ┌──── OFF ────┐
        │  (3V3D 待机) │
        └──┬──────────┘
   ONOFF_KEY│(长按2s)
           ▼
         BOOT ──(各电源就绪)──► STANDBY ◄──── AC 拔出/通路切换
                                  │
                  ┌───────────────┴───────────────┐
                  │ 检测 AC_IN 是否接入            │
                  ▼ (mod_metering.vin_v > 阈值)   ▼ (vin_v ≈ 0)
         ┌── AC 接入分支 ──┐              ┌── 电池供电分支 ──┐
         │                 │              │                   │
         │  用户二选一选择  │              │   仅允许逆变输出  │
         │      ▼           ▼              │        ▼          │
         │  BYPASS      CHARGING           │   INVERTING       │
         │ (AC_CTRL    (CHG_IN+CHG_OUT     │  (接触器+INV_OUT  │
         │  闭合)       闭合)              │   闭合)           │
         │  PATH_BYPASS PATH_CHARGE        │   PATH_INVERT     │
         │      │           │              │        │          │
         │      └─ 切换时先全断再吸合 ─┘    │        │          │
         └────────┬────────┘              └────────┬──────────┘
                  │                                 │
                  └────────────► FAULT ◄───────────┘
                  (过压/过流/过温/低SoC/AC 断电/按键)
                              │
                              ▼
                          SHUTDOWN → OFF
```

### 7.1 AC 接入判定与通路选择规则

| 输入条件 | 允许通路 | 禁止通路 | 默认动作 |
|---|---|---|---|
| AC_IN 接入 (vin_v > 180V) | PATH_BYPASS 或 PATH_CHARGE（二选一） | PATH_INVERT（逆变强制禁止） | 上电默认 PATH_BYPASS；用户通过按键/蓝牙/屏切换到 PATH_CHARGE |
| AC_IN 未接入 (vin_v < 50V) | PATH_INVERT（仅此一条） | PATH_BYPASS / PATH_CHARGE | 自动进入 PATH_INVERT（若 SoC 允许） |
| AC_IN 在接入中掉电 | PATH_NONE → PATH_INVERT | — | 先切 PATH_NONE（防瞬态短路），稳定后转 PATH_INVERT |
| AC_IN 在逆变中突然接入 | PATH_NONE → 等用户选择 | PATH_INVERT 立即切断 | 强制切到 PATH_NONE，蜂鸣提示，等用户在 BYPASS/CHARGE 间选择 |

**切换时序**（任一通路切换，由 mod_acswitch 内部强制）：
1. 断开当前所有通路继电器
2. 死区延时 ≥50ms（防止跨通路短路和电弧）
3. 吸合目标通路继电器
4. 50ms 后回读继电器状态，失败则进入 FAULT

### 7.2 用户选择接口（AC 接入时二选一）
- 按键 K1 (PC0)：切换 BYPASS ↔ CHARGE
- 编码器 (PC11/PC12)：菜单选择
- 蓝牙命令 (UART6)：`SET PATH=BYPASS|CHARGE|INVERT|NONE`
- 串口屏 (UART4)：触摸按钮
所有选择请求先发到 svc_eventbus，由 TaskState 校验 AC 状态后调用 `mod_acswitch_select_path()`。

**进入 FAULT 立即动作**（TaskProtect）：
1. 调用 `mod_acswitch_select_path(PATH_NONE)` 切断全部 AC 继电器 + 直流接触器
2. 蜂鸣器报警 + LED2 红色闪烁
3. 通过 svc_eventbus 广播，TaskState 推进到 SHUTDOWN
4. 写入日志到 W25Q128

## 八、保护策略清单（app_protect）

| 类别 | 触发条件 | 来源 | 动作 |
|---|---|---|---|
| 电池过压 | Vbat > bat_ovp_mv (MAX17263) | mod_battery | 停充电，断 CHG_OUT |
| 电池欠压 | Vbat < bat_uvp_mv | mod_battery | 停逆变，断接触器 |
| 过温 | NTC > otp_deg | mod_battery | 限功率/停机 |
| 输入过压 | Vin > inv_ovp_v | mod_metering | 断 AC 输入 |
| 输出过流 | Iout > inv_ocp_a 持续 100ms | mod_metering | 断 INV_OUT |
| 输出短路 | Iout >> ocp 且 Vout 塌陷 | mod_metering | 全切断 + 锁定 |
| **通路互锁违反** | AC 接入时检测到 INV 通路电流，或 BYPASS/CHARGE 同时带电 | mod_metering + mod_acswitch | 立即 PATH_NONE + FAULT 锁定 |
| **AC 接入时逆变** | vin_v>180V 且 INV_OUT 有输出电压 | mod_metering | 强制断 INV_OUT，转 PATH_NONE |
| **双通路同时导通** | BYPASS 与 CHARGE 继电器同时吸合（回读异常） | mod_acswitch | 全切断 + FAULT |
| 电量计告警 | ALRT 引脚 | EXTI | 转换为具体故障 |
| 看门狗 | 任务心跳超时 | TaskWatchdog | 复位 |
| 软件异常 | HardFault | NVIC | IWDG 复位 |

## 九、电源管理时序（app_power）

上电顺序：
1. 按下 ONOFF_KEY (PB3) → TaskPower 收事件
2. 拉高 PB4_PWR_EN（使能主 DC-DC）→ 等 +12V/+5V 稳定（ADC 检测或固定延时 200ms）
3. 依次使能 3V3U(默认常通)/3V3A/3V3D/3V3G（按 LDO EN，未在原理图标出则视为常通）
4. 唤醒蓝牙 PA2_BLE_WKUP、点亮显示屏 +12V_LCD
5. 通知 svc_state：BOOT→STANDBY

下电顺序（逆序）：
1. 切断所有强电
2. 关显示屏、停蓝牙
3. 拉低 PB4_PWR_EN
4. 进入 OFF（仅 RTC + VBAT 维持）

## 十、对接现有 CubeMX 代码的方式

不动 CubeMX 生成区域（`USER CODE BEGIN/END` 之间写自有代码），新增 `App/Service/Module/Driver/BSP` 目录通过 `.cproject` 加入构建路径。具体落地步骤：

1. **BSP 层**：在 `bsp_io.c` 中封装 `BSP_AC_CTRL(1)` 这类语义宏，屏蔽 `HAL_GPIO_WritePin(PD1_AC_CTRL_GPIO_Port, PD1_AC_CTRL_Pin, ...)`。
2. **Driver 层**：`drv_hlw8110.c` 通过 `huart2/huart3` 收发；`drv_max17263.c` 通过 `hi2c1`；`drv_w25q128.c` 通过 `hspi2` + GPIO 控制 CS/WP/RST。
3. **UART 收发**：在 `stm32f4xx_it.c` 的 `USARTx_IRQHandler` 中调用 `osSemaphoreRelease` 唤醒对应任务，DMA 空闲帧结束检测在 `HAL_UARTEx_RxEventCallback`。
4. **任务创建**：在 `freertos.c` 的 `MX_FREERTOS_Init` 中替换 `defaultTask` 为各模块的 `osThreadNew`。
5. **配置项**：FreeRTOSConfig.h 调整 `configMAX_PRIORITIES=9`、`configTOTAL_HEAP_SIZE` ≥ 32KB、`configUSE_TIMERS=1`、`configCHECK_FOR_STACK_OVERFLOW=2`。
6. **看门狗**：IWDG 已初始化，TaskWatchdog 1s 喂狗，并检查各任务 `last_tick`。

---

## 十一、可测试性与扩展性

- **HAL 解耦**：每个驱动通过函数指针表 `drv_xxx_ops_t` 暴露，便于在 PC 上 mock 测试。
- **协议层与传输层分离**：HLW8110/MAX17263 协议解析独立，不依赖具体 I2C/UART 句柄。
- **配置驱动**：保护阈值、状态机时序、任务周期均放入 `config_t`，运行时可通过调试口或蓝牙修改并落盘。
- **日志分级**：DEBUG/INFO/WARN/ERROR，可动态切换输出通道（RTT/UART1/Flash）。
- **版本管理**：Flash 中保留 `config_t.magic + version`，启动校验，升级后可迁移字段。

## 十二、落地优先级建议

1. **Phase 1**：BSP/Driver 骨架 + mod_battery + mod_metering（能读到电池与电参数）
2. **Phase 2**：svc_state + svc_eventbus + TaskState（基础状态机能跑通 OFF↔STANDBY）
3. **Phase 3**：app_power（开关机时序）+ app_protect（保护切断）
4. **Phase 4**：app_charge + app_inv + app_acpath（完整能量通路）
5. **Phase 5**：mod_display + mod_ble + mod_hmi + svc_config（人机交互与持久化）
6. **Phase 6**：日志、看门狗心跳、参数标定、长期稳定性
